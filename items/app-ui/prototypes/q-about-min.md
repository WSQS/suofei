## 1 · 这一块的形态（**只有一种形态**）

```
更新块（卡片：surface 底 ＋ 1px 发丝线 ＋ 4px 圆角 ＋ 无阴影）
└─ flex column
   ├─ <button type="button">检查更新</button>     ← 上方：唯一的动作
   └─ <p>状态说明文本</p>                          ← 下方：一段字，原地替换
```

**实测（430，六块全都一样）**：

## 2 · 五种真实状态（**文案逐字**，版本号／字节数／原因是运行时占位）

文案逐字来自真实实现 `android/app/src/main/java/dev/sopho/suofei/ui/UpdateStatusText.kt`（自检把页面渲染出来的那串与脚本的**独立期望**逐字比对，三个视口各跑一遍）：

| 状态 | 真实协议分支 | 状态说明文本（**逐字**） | 唯一按钮 | 430 行数 | 更新块高 |
| --- | --- | --- | --- | --- | --- |
| 尚未检查 | `UpdateStatus.Idle` | `尚未检查。` | 可用 | 1 | 93.13 |
| 检查中 | `UpdateStatus.Checking` | `正在检查…` | **禁用** | 1 | 93.13 |
| 已是最新 | `UpdateStatus.UpToDate` | `已是最新内容（远端 ⟨内容版本⟩）。` | 可用 | 1 | 93.13 |
| 已下载并切换生效 | `UpdateStatus.Activated` | `新内容 ⟨内容版本⟩ 已下载、校验通过并已切换生效（⟨字节数⟩ 字节）；返回目录后采用。` | 可用 | 2 | 116.09 |
| 失败·旧内容保留 | `UpdateStatus.Failed` | `更新未生效，旧内容保留：⟨原因⟩` | 可用 | 1 | 93.13 |
| 〔夹具〕失败·最长原因 | 同上 `Failed` 的最长一支 | `更新未生效，旧内容保留：SHA-256 不符（清单 ⟨清单 SHA-256⟩，实际 ⟨实际 SHA-256⟩）；已丢弃下载结果，保留旧内容（下载/校验未通过）` | 可用 | **3** | 139.06 |

**三条要写清的事实**：

1. **「检查中」覆盖检查＋下载＋校验＋切换全过程**：真实实现里下载与校验都发生在**同一次** `checkAndUpdate` 调用里，屏上一直是 `正在检查…` ⇒ 本页**没有**发明「下载中／校验中」这类中间态（协议里也没有）。
2. **「检查中 ⇒ 唯一按钮禁用」是真实规则**：`AboutScreen` 里 `enabled = state.updateStatus !is UpdateStatus.Checking`。自检在两个地方各断言一次（默认态的那一块 ＋ 单选到「检查中」时），并要求**其余五个状态按钮都可用**——这就是「按钮可用性」的全部差别。
3. **夹具那一格不是产品状态**：它只用来量「最坏的一条如实报错」会不会把排版撑坏。两个哈希是**运行时值**（占位符，没有写死任何 64 位哈希）；块外的标签写明「夹具：最长失败原因／不属于产品状态」。

## 4 · 自检怎么跑、它断言了什么

```bash
node items/app-ui/prototypes/check-about-min.mjs                 # 断言 + 重出 q-about-min.430.png
node items/app-ui/prototypes/check-about-min.mjs --no-shot       # 只跑断言（失败断言数 0（PASS 1121））
node items/app-ui/prototypes/check-about-min.mjs --all-shots     # 连 320／1180 的图也写出来（三张都在上限内）
node items/app-ui/prototypes/check-about-min.mjs --only=430      # 只跑某一个视口（排查用）
node items/app-ui/prototypes/check-about-min.mjs --selftest-chrome
```

- **当前结果：`失败断言数：0`（PASS 1126）**；`--no-shot` 下同样 0（PASS 1121）。
- 只用 Node 内置模块（`fetch`／`WebSocket`／`net`），**不装包、不联网、不起静态服务**（直接开 `file://`）；仓库根靠**向上查找 `prototype/css/theme-tech.css`** 定位（**不写死层级**），CDP 端口**先向内核要一个空闲端口**（不写死）。
- 断言覆盖（摘要）：
  - **令牌快照**逐项比对主题文件（29 条，值不一致 0、缺失 0）；没有「声明了却没用」的令牌；页面里每个 `var()` 都有声明；快照的依据 blob ＝ `git hash-object` 的结果，且该文件相对 HEAD 无本地改动。
  - **每块恰＝视口宽、块左沿 0**（六块 × 三个视口，默认态与六个单态各查一遍）；内容列宽＝公式复算值；列外余白＝(V−C)/2；行内沿 16.8px。
  - **无横向溢出**：默认态、**六个单态（含最长失败文案）** 各查一遍；同时盯 `documentElement.scrollWidth`＝`body.scrollWidth`＝**`visualViewport.width`**＝视口宽（防 `shrink-to-fit` 撑开布局视口那种假象）。
  - **可点元素只有 `<a href>` 与 `<button type=button>`**（全页枚举）；没有内联 `onclick`；页面里 `<details>/<summary>` 数 0。
  - **状态文案逐字**：先比页面导出的定义（`window.__ABOUT_MIN__`），再比 DOM 真的渲染出来的那一串；**检查中 ⇒ 按钮 disabled**，其余五态可用。
  - **同一形态**：六块的结构序列、更新块子元素序列、状态文本的颜色／字号／行高**各自完全相同**。
  - **更新块里只有两样**：可点元素恰 1、小标题 0、分区 0、步骤 0、`lastcheck` 0、折叠 0、来源 0；**按钮在状态文本上方**（几何：按钮底 ≤ 文本顶）；按钮**不是满宽条**。
  - **固定清单**：A3 次序、版本相邻组**不含来源**、仓库＝完整 URL 且无提示且在块尾、应用名＝索斐、块内没有笔记夹具。
  - **自包含**：静态无 `<link`／`<script src`／`@import`／`url(http`／`fetch(`／`XMLHttpRequest`；运行时用 CDP Network 收请求并断言**非 `file://` 的请求 0 个**；无 JS 报错。
  - **PNG**：**先量高度**再决定拍不拍；超上限（16000 像素）就**如实报错、不落盘**；自己解析 IHDR ⇒ 像素宽 ＝ 视口宽×2、像素高 ＝ 截图区 CSS 高×2、文件非空；截图区左沿 0、宽＝视口宽。
  - **边界自证（真的跑一次子进程）**：`CHROME_BIN=C:/definitely/not/here/chrome.exe` ⇒ **退出码 2**、stderr 说明原因、stdout 里**没有**「失败断言数：0」（**不假装通过**）。当前结果：**通过**。

**一条本轮踩到的几何坑（已改，写在这里免得别人重踩）**：按钮一开始是 `display:inline-block`，于是它被**行盒的半个行距**往下推了 5.8px（距块顶 13.8 → 实测偏移）—— 量出来才发现。改成更新块 `display:flex; flex-direction:column` ＋ 按钮 `align-self:flex-start` 后，按钮顶＝块内沿（13.8px），且仍然是内容宽（80.02），**不是满宽条**。

## 5 · 本页**没表达什么**（诚实清单）

1. **更长的那条真机失败文案没有画成真实长度**：夹具用的是占位符 `⟨清单 SHA-256⟩`；真机上那两个哈希**各是 64 个十六进制字符** ⇒ 真实那一行会比图里**更长**。本页的做法是：状态文本 `overflow-wrap: anywhere`（自检断言），所以**长度只影响折行数，不影响横向溢出**；但「128 个十六进制字符到底折几行」**本页没有实测**。
2. **失败态不换色**：按用户原话「同一形态，只换文本与按钮可用性」⇒ 五种状态的字色完全相同（自检断言「六块状态文本颜色 1 种」）。**代价**：失败在颜色上**不可辨**，只能靠读字（`规范 §4.2` 里那套 `--warn-*` 通道本页没有用上）。要改这一条，就是改「同一形态」的边界。
3. **不画「来源（内置／已下载）」**：共用版本信息里已排除它，而「放进更新块要不要显示」**仍未定** ⇒ 本页**不画、也不假装已定**（页面明面上写着这一条）。
4. **`FailureKind` 的完整覆盖不做**：只画了一条代表性的失败（`⟨原因⟩`）＋ 一条最长夹具；`FORMAT_TOO_NEW`／`APP_TOO_OLD`／`MANIFEST_INVALID`／`IO` 的差别只在 `reason` 文本里，本页不为它们的完整覆盖背书 —— 那属「内容格式／更新协议」那条线。
5. **`UpdateStatus.Error`** 不画（生产代码里从未被构造）。
6. **顶栏与返回入口**不画（两端共有的外壳，不在本轮范围）；**APK 的更新检查／下载**、其它位置的升级提示**完全不涉及**（这一页只做内容更新）。
7. **点击后的真实行为**：本页的按钮都**不触发任何更新逻辑**；「按下会怎样」在真实实现里由状态映射表达（见 §2），不是本页真跑。
8. **断点／媒体查询、滚动容器、安全区、横竖屏、系统字号放大、字体回退差异**都没有表达（宽度只用已选口径一条）；**深浅色／主题切换**：单主题已定，不涉及。
9. **未在真机／Android 模拟器上验**：所有数字都只在**本机无头 Chromium**（`file://`、DPR 2）上测过；**截图不能代替真机手感**。本页是 HTML 原型，**不是** Kotlin/Compose 实现。
10. **没画进图里的两个视口**：320 与 1180 的行为**照样被查**，但它们的 PNG 默认不落盘（`--all-shots` 才写；本轮实测三张都在截图上限内：320 → 640×6968、430 → 860×6250、1180 → 2360×5298）。
