> **材料，不是实施。** 本页只回答一件事：**视觉折行时，要不要／怎么「优先在句读／半句边界断开，标点归前句」**，

> **不排推荐、不排序、不写推荐**：a／b／c／d／e 各档候选都是**并列**的；

## 0 · 为什么有这一页

上一轮（`items/app-ui/prototypes/q-break.*`，已在 `history/` 留档的是更早的轮）量过的是**「浏览器默认怎么断」**：凑满字位 ＋ 默认禁则。
用户这一轮把方向定死了，而且**明确否定**了「凑满字位、只额外防一下行首标点」那种：

> 视觉折行时**优先在句读／逗号后的半句边界**断开，**标点归前句**；**两个视觉行都继承居中**。
> 例：`行行重行行，与君生别离。` ⇒ **`行行重行行，` ／ `与君生别离。`**

所以本页要做的是**两种断法的逐字对照**（同一容器宽、同一段文字，只差断法这一条），
并把「按句读断」这件事上**真正要定的边界**（a–e）与**实现代价**分开陈述。

## 3 · 两种断法是什么（② 是**一个具体版本**，不是唯一可能的「按句读断」）

| | ① 浏览器默认（**现状**） | ② 按句读断（用户要的方向） |
| --- | --- | --- |
| 断在哪 | 凑满字位，再按默认禁则（收尾标点不起行、开启标点不留行尾） | **优先在句读／半句边界**断开，**标点归前句** |
| 本页怎么渲染 | 原样文本，不写任何断行 CSS | 把文字**按句读切成段块**（每段一个 block）；段内若仍装不下，才由浏览器继续按字位折（＝候选 d） |
| 本页的具体版本 | —— | 候选集 `{，。！？；：、}`；**窗口＝容器宽（字位数）**；窗内取**级别最高**的句读位置、同级取**位置最大**；窗内没有候选 ⇒ 视作「半句本身仍超宽」，退到**字位下界**并**施加禁则** |
| 级别表（本页 ② **实际采用**的那一档） | —— | `。！？ = 2`，`，、；： = 1`（＝ `rank_b1`；**不是推荐**，B 块把三档并列） |

⚠ **② 不是一个已经定死的规则**：上面每一个选择（候选集含哪些标点、级别谁高谁低、窗口内怎么挑、半句仍超宽时怎么降）都是**可变的**，
a–e 五组候选就是把它们摊开。本页挑一档来画，只表示「**本页得挑一个**」，**不表示推荐**。

**自检把这件事查实了**：脚本里**独立实现了一份** `greedy`（①：凑满字位＋禁则）与一份 `segs`（②：按句读切段），
把页面渲染出来的**每一行逐字**与模型复算的行比对（[5] [6]）；不一致就报错。所以下面表里的文字不是抄图注，是**两边独立算出来对上的**。

## 6 · 要产出 3：边界候选 **a–e**（**并列、不排序、不写推荐**）

### a · 宽屏（内容放得下时）要不要也强制按句读拆

- **a-① 只在真超宽时才拆**（＝现状）：装得下 ⇒ 1 行、不折。实测：真实第 1 行在 320／430／1180 上**都是 1 行**。
- **a-② 一律按句读拆**（装得下也拆）：同一容器同一段文字 ⇒ **2 行** `行行重行行，` ／ `与君生别离。`。

⚠ 用户**没有要求**强制拆；本页只把两者并列。**选 a-② 的后果**：宽屏上每一句都被拆成两行（诗页行数翻倍）；**选 a-① 的后果**：宽屏上看不到句读断行，只有在真装不下时才生效。

### b · 多个标点的优先级

三组**并列**的顺序（本页 ② 渲染时**采用**的是 b-①，那只表示「本页得挑一个来画」）：

- **b-① 两档**：`。！？` 最高；`，、；：` 同层次之；同一档取**位置最大**。
- **b-② 三档**：`。！？` ＞ `；：` ＞ `，、`。
- **b-③ 逗号最优先**：`，` ＞ `。！？` ＞ `、` ＞ `；：`。

实测差别见 4.2 的 B 表：b1 上 b-①＝b-③ ≠ b-②；b2 上 b-①＝b-② ≠ b-③。**⇒ 这条必须定，否则同一段文字在不同实现里断点不同。**

### c · 无标点的长句怎么办

- **c-① 按字位断＋避头／避尾禁则**（＝浏览器默认）。
- **c-② 按字位断、不写禁则**（`line-break: anywhere`）。
- **c-③ 允许溢出**（不折）。
- **c-④ 缩字号**（缩到装得下）。

实测（4.2 的 C 表）：**c-① 与 c-② 逐字相同**（无标点 ⇒ 禁则没有作用对象）；c-③ 会**越出 142.13px**；c-④ 要把字号缩到 **7.28px**。

### d · 半句本身仍超宽

- **d-① 在更小边界断**（用「、；：」这类更小边界）。
- **d-② 在字位处断＋禁则**（＝交给浏览器默认在该半句内折）。
- **d-③ 允许溢出**。
- **d-④ 缩字号**。

实测（4.2 的 D 表）：d-① ＝ 6／8／1（**多出一行、尾行只有 1 个字**）；d-② ＝ 8／7（每行更满、但不尊重那个「、」）；d-③ 越出 **124.36px**；d-④ 字号缩到 **9.06px**。

### e · 断点是否同时受禁则约束

- **e-① 只按句读、不施禁则** —— 实测：**「，」起行**、**「（」留行尾**（违反禁则）。
- **e-② 句读＋禁则** —— 实测：不违反。
- **e-③ 字位断、不施禁则**（`line-break: anywhere`）—— 实测：**同样违反**（与 e-① 逐字相同）。
- **e-④ 字位断＋禁则**（＝默认）—— 实测：不违反（与 e-② 逐字相同）。

⇒ **结论（可核的实测）：禁则不是「按句读断」自动带来的**；只有把禁则**同时**施加到「退到字位下界」那一步上，收尾标点才不起行、开局标点才不留行尾。

## 7 · 要产出 4：实现代价（**如实**）

**先说一句硬结论：纯 CSS 做不到「按标点优先断」。** 证据有两层：

1. 本机可用的 CSS 属性里，`line-break` 只有 `normal／strict／loose`（都是**字位 ＋ 禁则**，没有「优先在标点后断」这个表达）；`hanging-punctuation` 本机 Chromium **不支持**（上一轮 `q-break` 实测 `CSS.supports("hanging-punctuation","allow-end") == false`，本轮沿用同一结论）。
2. 本页 F 块实测：**纯 CSS 那一列拿不到 ② 的断点**（`甲乙丙丁戊，己庚` ／ `辛壬癸` ＝ 8／3，而 ② 是 `甲乙丙丁戊，` ／ `己庚辛壬癸` ＝ 6／5）。自检把这一条写成断言（[13]）。

**四条实现路径的代价与风险（并列，不排推荐）**

| # | 做法 | 代价 | 风险 |
| --- | --- | --- | --- |
| ① | **分段块 ／ `<br>`**（把每个半句渲染成一个块级元素；本页 ② 就是这么画的） | 渲染层要多一份「分行结果」；**源 Markdown 不改** ⇒ **Web 与 Android（原生 Compose，不是 WebView）各做一次** | 两端必须是**同一份规则**，否则两端断点不同；宽窄变化时要重算（本页用的是固定 px 容器，产品里得按真实可用宽算） |
| ② | **逐行 `<span>` ＋ 脚本重排** | 每次重排／字号或字体变化都要重算 | 脚本算出的断点与浏览器**真实**断点可能不一致（本页另留隐藏参照核对这一条） |
| ③ | **读回浏览器换行位置后重排**（先用浏览器折一次、量出断点，再按句读拆开） | **必须等布局完成再量**，且要在 resize／字体加载后**重新量** | 字体回退会改断点（本机解析到的是 `Microsoft YaHei UI`）；量测与重排之间会有一帧跳动 |
| ④ | **纯 CSS** | —— | **做不到**（见上面两层证据） |

⚠ 「源 Markdown 不改、只在渲染层断」这条路的**直接后果**是：**两端各做一次**。本页只把它写在代价里，**没有**在 Android 侧验过（Android 是原生 Compose；本页只在**本机无头 Chromium** 里跑过）。
