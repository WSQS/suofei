## 5 · ③ 与上一版的变化

| 变化 | 具体 |
|---|---|
| **删掉 A／B／C 三入口** | 原型条上不再有模式切换；页面只有一版「顶部 tab」；`data-mode` 控件整块不存在（断言） |
| **删掉「选本列表 → 独立诗目页」这一层** | 不再有「列出所有选本、每行带已收录数」的列表页，也没有「某选本一页」的下钻页；标签 tab 自己就是**一份与朝代页同构的可展开列表** |
| **删掉标签页的全部数量** | 组头计数、页面元信息「本库已收录 N 首 · 按选本次序」、子诗目前的 `001` 悬挂序号——全部删除 |
| **子诗目去序号** | 行＝题名＋作者，题名左沿＝标签名首字左沿；序号字段 `orderInTag` 仍在夹具数据里（不显示≠删除） |
| **文案「选本」→「标签」** | 页面文案一律「标签」；「选本」只出现在归档目录名与本说明里，应用页面不出现 |
| **朝代 tab 未动** | 仍是 3 组、计数 `[19]/[2]/[1] 首`、`[+]/[−]` 悬挂、初态收起、整行可点（断言逐条守） |
| **上一轮检查口径作废** | 上一版 README 的「8 条逐条点名」和「本库已收录 N 首」那套口径**已被本轮用户决定替代**，只在归档目录里保留作审计线索，**不再作为本轮检查口径**；本轮断言按上面 ① 的要求重写（见 §8） |
| **零成员标签不再渲染**（本轮返修） | 判据＝**成员数 ≥ 1**（该标签在本库至少关联 1 首诗）；成员数 0 的标签**不渲染**：不出现组头、不出现展开按钮、不出现任何空态文字（用户 2026-10-18：「标签下面没有诗就该没有标签」）。夹具里那条零成员标签（玉台新咏）**仍留在数据里作反例**，只是不出界面；也不是删除标签定义、不是给它造作品；无标签的诗仍留在朝代页 |

## 6 · ④ 未表达（诚实清单）

1. **Android 系统返回／手势**：**未实现、未验**。本原型只有 Web 侧（页面「返回」＋浏览器后退，两者都验过，各退一层）。层级上「每页一个历史条目」与之同构，但**不等于已验证**。
2. **跨刷新／重启的状态记忆**：展开状态与滚动位置只在**当前页面内存**；刷新回到初态（标签页全部收起、滚动归 0）。跨重启没做也没定。
3. **真机／WebView／iOS**：只在无头 Chromium 上跑过；触摸手感、点击延迟、滚动惯性、安全区都没验。
4. **无障碍**：只写了 `role=tablist/tab`＋`aria-selected`、`aria-expanded`、记号 `aria-hidden`；**没有**核键盘焦点顺序、没有 TalkBack 朗读核验、没有重新核对比度。
5. **同名不同标签**（`tag-semantics` §2.5）：界面**没有**区分方式（例如「唐诗三百首（某本）」）；标签行只有显示名，没限定词。
6. **标签改名与稳定标识**（§2.6）：夹具里 `id` 与显示名分开写，但界面上看不出差别；没有演示「改显示名而归属不断」。
7. **一首诗属于多个标签**：数据里有（`行行重行行` 同时属「古诗十九首」与「汉魏六朝诗选」），但界面**不显示「这首诗有哪些标签」**——只有单向「标签 → 诗」。
8. **标签是否只承载选本**（§2.10 未定）：本轮**不假设**。所以夹具里特意放了一个主题类标签「咏怀」；若将来语义收敛成「只有选本」，页面文案不用改，但夹具这个例子要换。
9. **标签自身的排序**：本轮按夹具数组顺序（古诗十九首 → 唐诗三百首 → 汉魏六朝诗选 → 咏怀）；标签多了怎么排（拼音？手工？）**未定**。⚠ 排序里已不再出现零成员标签（它不渲染），所以「不可见标签怎么参与排序」这个问题本轮**没有表达**。
10. **标签很多时的表现**：只有 4 个组头，没有表达 20／50 个标签时的滚动与分组。
11. **全库无标签时的整页空态未表达**：本轮只定了「零成员标签不渲染」；若**所有**标签都没有诗（或本库一个标签都没有），标签页就是一片空白（只剩顶部两个 tab 与「关于」）——用户**本轮没说**这种情况该怎么办，因此**没有**实现任何整页空态文案，此处只记录为未表达。
12. **其他浏览轴**：作者视图、体裁视图一律没做（本项只要「朝代 ＋ 标签」）。
13. **宽度只出 320 与 430**：834／1180／横屏没出图（宽度口径本身是已选的）。
14. **长题名折行、超长诗行**：没放这类夹具，也没表达（已选规则在 `ui-poem`，本轮不重开）。
15. **关于页**：顶部「关于」是不导航的控件（`title` 写了「本原型不实现关于页」）。
16. **详情 Markdown 全子集**：只渲染真实 `detail` 里出现的三类元素（`###` 小标题、`- ` 列表、段落＋`**粗体**`），不是通用渲染器；本库这些诗都没有笔记 ⇒ 笔记入口整块不存在。
17. **`captureBeyondViewport` 的已知坑（记录一次踩坑）**：整页渲染 + 裁切时，Chromium 会临时重排，页面高度一变滚动就被夹到另一个值，而**顶部 sticky 原型条**已按那个值贴住 ⇒ 图里条的位置与裁切起点对不上（第一次跑就撞到：JS 读到 y=520，图里条却画在 688、条上读数也是 688）。所以**「滚动位置本身就是证据」的那张图改用视口直捕**（`05`），其余仍用整页渲染 + 裁切。改的是截图方法，不是页面。

## 8 · 自检（**67 条断言 / 失败 0**，可复跑）

```sh
node items/tag-views/prototypes/check-tag-views.mjs            # 出图 + 断言
node items/tag-views/prototypes/check-tag-views.mjs --no-shot   # 只断言
```

按本轮要求重写的断言（不是上一版那套）：

- **无数量**：标签页组头没有 `.gcount`；标签页文本里没有任何计数／「本库已收录」／`[N]` 编号；展开与收起两种状态都查。
- **零成员标签不渲染（本轮返修的成对三条，替代旧的「空标签可展开」三条）**：
  1. 夹具**数据里确实还有**那条零成员标签（运行时读 `window.__TAGFIX`：`TAGS` 共 5 条，`yutai-xinyong` 的成员数 `= 0`）——证明反例存在；
  2. **页面文本里不出现**它的名字（无 `[data-ghead="tag:yutai-xinyong"]` 组头、无 `tempty`、无「还没有诗」类文案）；
  3. **有诗的 4 个标签照常出现**（组头名与夹具逐步一致、顺序不变），且展开后子诗题对齐规则不变（见下一条）。
- **组头可点**：**点在组名上**（不是点记号）也能展开／收起；`aria-expanded` 同步。
