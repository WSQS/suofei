# 项：内容标签的域场景与语义（首稿 · 待用户/对话侧确认）

> 父项：[`content-tags`](../content-tags/item.md)。**本文只写「标签在我们这里指什么」并给反例/边界例子**，不设计字段、不设计界面。

## 1. 标签＝「归属/选本」，不是这些东西

用户给的两个例子（**古诗十九首**、**唐诗三百首**）都是**作品集合 / 选本归属**。因此标签**不等于**：

| 容易混的 | 为什么不是 | 撞车例子 |
|---|---|---|
| **朝代分组** `dynasty` | 朝代是**分组轴**（汉/唐/近现代…），一首诗只能有一个，且它决定目录的分组 | 若把「唐诗三百首」当朝代，会把「唐」这一组的语义抹掉 |
| **体裁** `genre` | 体裁（五言古诗…）是**形式**，与「被哪个选本收」无关 | 同一首五言古诗可属任意选本 |
| **目录/文件夹** | 路径是**ID 的来源**（`杜甫/梦李白二首·其一.md` ⇒ `杜甫-梦李白二首·其一`），一首诗只有一条路径 | 不能为「同时属两个选本」把作品复制两份（见 §2.2） |
| **`source`** | `source` 是本仓**采用的底本与出处**（如《全唐诗》卷二百一十八） | 底本可用《全唐诗》，而归属是《唐诗三百首》——**两件事可能不同** |
| **`orderInSource`** | 它是**本仓底本内的逐首次序** | 选本有自己的编次（见 §2.8） |

## 2. 具体例子（用来钉边界，**不是真实数据**）

1. **一首诗一个标签**：《行行重行行》→ `古诗十九首`。（不是 `汉`、不是 `五言古诗`、不是目录名、不是 source。）
2. **一首诗多个标签**：《X》同时被 A 选本与 B 选本收 ⇒ 标签集合 `[A, B]`，**作品只有一条**（**不许为不同标签复制作品**）。
3. **无标签是合法状态**：现库里的《梦李白二首·其一/其二》若不属于任何选本 ⇒ **没有标签**，目录仍要能列出它们（不能因为「没有标签」就把诗藏起来）。
4. **「唐诗三百首」不能自动套给所有唐诗**：只有**该选本实际收录**的才打。⇒ 计数口径是「**本库已收录该选本 N 首**」，**不是**「该选本只有 N 首」；界面上不能写成「唐诗三百首（300 首）已全部收录」。
5. **同名不同选本**：两个不同编者/版本的《唐诗三百首》⇒ **不能只靠名字唯一定位**（要不要加限定、加在哪儿，未定）。
6. **标签改名**：把「古诗十九首」改成别的显示名 ⇒ **诗的归属不该因此断**（说明：标签需要**稳定标识**，显示名可改）。
7. **标签增/删**：新选本加入；某首被移出某选本（诗的正文不因此变）。
8. **选本内次序 ≠ `orderInSource`**：《唐诗三百首》有它自己的编次；本仓 `orderInSource` 是底本内次序。**两者可能不一致**，不能互相顶替。
9. **同一首诗、两个「次序」同时存在**：标签侧次序（选本编次）＋ 底本次序（`orderInSource`）——若都要表达，需要**分开存**（怎么存未定）。
10. **标签可能泛化到别的轴？？**（**未定，不许擅自限制**）：标签是否只承载「选本/集合」，还是也能表达**主题**（如「送别」）或**作者**（如「李白」）——**未定**。⇒ 实现候选**不得**写死「仅 collection-only」的假设，也**不得**据此自动扩库。

## 3. 明确未定（留给原型/用户）

- 「一首诗多标签」的**上限/是否排序**、标签**名字是否允许同名**到何种程度、**标签自身的元数据**（说明、来源、是否算「选本」）；
- 标签视图的**入口与切换形态**（tab？下拉？独立页？）——**不在本文钉**；
- 标签与**朝代分组**同时存在时，**目录默认视图**是否保留、如何共存；
- 字段集与 `formatVersion` 升版时机（**本阶段不动**）。

## 4. 写给下游（`tag-format` / `tag-views`）的约束

- 必须能表达 §2 全部 10 例；**至少**表达 2.1/2.2/2.3/2.4/2.8；
- **不得**为了标签而复制作品、**不得**改 `source`/`orderInSource` 的既有语义、**不得**要求为标签单独建目录；
- 若结论是「需要新字段」⇒ 记候选并标「将来按方案 B 升 `formatVersion`」，**本期不升**。
