# 项：内容标签与多浏览视图（能力总项）

> **当前阶段：方向已确认、字段与视觉均未定。**（用户 2026-10-18：「推进 tag，例『古诗十九首』『唐诗三百首』，意味着新的视图不止默认视图」）
> 本项只是**能力总项**：承载领域场景、术语指针、子项划分与退出条件。**具体理解与采纳锚由对话侧写在这里**。
> ⚠ 术语按 `CONTEXT.md` 的 Language 段：**内容标签（tag）不是 Git 发布 tag**；「浏览视图」＝同一诗库的不同组织与浏览方式，当前按朝代不再是唯一方式。

## 这一项要解决什么

用户想把诗的**归属**表达出来（例：某首诗属于《古诗十九首》这种**选本/作品集合**），并因此需要**「默认视图之外」的浏览方式**。
可拆三层（都在本项之下）：**MD 标注格式** · **数据字段** · **UI 视图设计**。三条工作线已确认，**三者都不是定稿**。

## 子项（三条工作线）

| 子项 | 一句话 | 状态 |
|---|---|---|
| [`tag-semantics`](../tag-semantics/item.md) | **域场景与标签语义**：标签到底指什么、用具体例子表达边界、哪些未定 | 首稿在制（调度侧起） |
| [`tag-format`](../tag-format/item.md) | **MD 标注写法 ＋ JSON 数据稿**：现有真实诗 → 候选 frontmatter → 完整 JSON 的三层对照 | 待派（独立 worker） |
| [`tag-views`](../tag-views/item.md) | **多视图 UI 原型**：朝代浏览＋标签相关浏览候选、入口/切换/列表/空与未收全/返回原视图与状态 | 待派（独立 worker） |

## 边界（**本阶段明确不做**）

- **不给现有 22 首真诗打标签**、不改 `content/`、不改 `schema/`、不改两端实现、不发布；
  **线上保持 `0.1.3` / 内容 `2026.10.16.26`**。
- 若将来字段集变化 ⇒ 按已选方案 B 应**升 `formatVersion`**；但**本阶段只写候选、不实际升**。
- 不把「标签」与 `source`（本仓采用的**底本/出处**）、`orderInSource`（**底本内逐首次序**）、文件路径派生的 **ID** 混为一谈（详见 `tag-semantics`）。

## 退出条件

用户看到**至少一个可操作的多视图原型**并给出方向反馈之后，才谈「字段集/视觉落地」；在用户评审前不动生产。
