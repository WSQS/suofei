## 4. `detail` 的「缺失」语义：写 `null` ↔ 键不存在

| 写法 | 产物片段 | 客户端读到什么 | 代价 |
|---|---|---|---|
| **写 `null`（键存在）** | `"detail": null` | 「我**明确知道**这首诗没有详情」——三态可区分：无详情 ↔ 字段不存在 | 是**契约现行口径**（§2.2：「可选字段缺失时写 `null`…不省略键，客户端无需判 `undefined`」）；产物略大（每首无详情的诗多一个 `null`） |
| **键不存在（omit）** | （`detail` 这一行不出现） | 「我**不知道**该不该有」——「无详情」与「旧产物/漏写」**无法区分** | 与契约现行口径**相反**，要**修订契约**并改客户端（每处都判 `undefined`）；⚠️ 并且与**字段集门的口径相冲**：门按**实际产物的键路径并集**算指纹（`tools/lib/field-set.mjs`），`detail` 时有时无会让「字段集」这件事**取决于内容** —— 当**没有任何一首**有详情时，`detail` 这条路径**根本不会出现** ⇒ 「机械可断言」的前提被打破 |

关键差别一句话：**`null` ＝「明确知道没有」；缺键 ＝「不知道该有没有」。**
本稿 `json/*.json` 按现行契约**都写了 `null`**（**样例如此，不代表已采纳**）。

## 5. `## 详情` 的分界：从哪起、到哪止？

**现状：未定。** `demo.mjs` 目前按**候选 1**实现 —— 那只是「让告警可运行」的临时写法，**不是采纳**。

| 候选 | 分界规则 | 代价 / 风险 |
|---|---|---|
| **1. 到下一个任意 `## ` 止**（草案） | 从**第一个** `## 详情` 起，到下一个以 `## ` 开头的行（或 EOF）止 | 规则最少；但详情内部**不能再出现 `##`**（只能用 `###` 及更深）；作者手滑写一个 `##` 就**提前断节**；第二个 `## 详情` 会被当成「另一个节」 |
| **2. 到下一个「已知具名节」止** | 到下一个已知名节（`## 笔记`）止；**未知的 `## X` 行当作详情内容** | 未知节不会吞掉后面内容；但**拼写错误会静默变成详情文本**（如 `## 詳情` 繁体、`## 详情 ` 多空格），错误不再显形 |
| **3. 详情必须是最后一节（到 EOF）** | `## 详情` 之后全部归详情，直到文件末尾 | 详情内部**最自由**（可含 `##`）；但**强制顺序**：`## 笔记` 不能跟在详情后面（与现有样例顺序相反），且「详情＋笔记」两节无法都在详情之后 |
| **4. 显式结束标记** | `## 详情` … 到 `<!-- /详情 -->`（或 `## 详情结束`）止 | 无歧义、详情内部可含 `##`；但写作者要记住配对标记，并给工程引入一种**新语法**（客户端与校验都要认） |
| **5. 围栏包裹** | `## 详情` 后接一个 ` ```md ` 围栏，详情＝围栏里的内容 | 切分天然清楚、与围栏能力复用；但作者要多写一对围栏，「整节」的语义变成「围栏内容」，与直觉有偏差 |

**它影响什么**：本稿所有样例**都不触发**这条歧义（详情内部只用 `###`）⇒ **无论选哪个，现有样例的产物都一样**；差异只在**详情内部出现 `##` 时**（`fixtures-ambiguous/ambiguous-detail.md` 就是这种输入）。

## 6. 围栏里的 `##` 算不算切分点？

**判据（说清「什么才算切分点」）**：① 切分点 ＝ 行首**恰好** `##` ＋ 一个空格（`^##\s`）；`###` **不匹配**，单个 `#`、行中间的 `#` 都不匹配。② **代码围栏内的行一律不是切分点** —— 识别前必须先跟踪围栏状态（行首 ` ``` ` 或 `~~~` 开闭配对）。③ 正文里以 `#` 开头的行不匹配 `## `，本来就不是切分点；但它是「诗行里混进 Markdown 标题符」的污染信号，**校验会响**。

| 候选 | 行为 | 代价 |
|---|---|---|
| **① 支持围栏**（演示按这个实现） | 跟踪围栏开闭，围栏内的 `##` 不当切分点 | 能写代码示例；但要有**状态机**，且**必须校验围栏成对闭合** —— 一个忘写的 ` ``` ` 会把**后面所有内容**吃进围栏（静默吞节） |
| **② 不支持围栏** | 约定详情里不写代码块，出现 ` ``` ` 直接报错 | 实现最简单、无状态机；代价是**不能写代码示例**（对考据文本影响不大，但与「最小 Markdown 范围是否含代码」联动：若不支持围栏，就不该把「代码」列进支持范围） |

**未定。** 但**无论选哪个**，「围栏里的 `##` 算不算切分点」都**必须显式回答** —— 演示因此对它**告警**（`fence-heading`）：本演示**不**把它当切分点，同时**大声报告**这里有一处需要决定的构造（`fixtures-ambiguous/ambiguous-detail.md` 里就有）。

## 7. 重复或未知的节怎么处置：报错 / 忽略 / 原样保留？

**现状：未定。** 演示**只告警、不止损**（不静默丢内容，也不替用户决定怎么处理）。

**7a. 出现两个 `## 详情`**

| 候选 | 行为 | 代价 |
|---|---|---|
| a. **报错**（编译失败） | 整份内容不产出，作者必须改 | 最安全、绝不丢内容；但一个笔误就**阻塞整批编译** |
| b. **后者覆盖前者** | 只留第二段 | **静默丢掉第一段**（考据内容损失，最危险） |
| c. **两段拼接** | 拼成一段 `detail` | 内容都在；但「拼」的语义（要不要加分隔、顺序）未定，读者也看不出这是两段 |
| d. **取第一个，其余告警并丢弃** | 用第一段，第二段只在告警里出现 | 产物可预测；但仍**丢内容**，只是「响了」 |

**7b. 出现未知的 `## X`（如 `## 校本`）**

| 候选 | 行为 | 代价 |
|---|---|---|
| a. **报错** | 编译失败 | 最安全；但**将来想加第三种节就得同时改编译器**（扩展性最差） |
| b. **忽略** | 该节及其内容消失 | 简单；但**静默丢内容** —— 与「宁可响、不许静默」正面相冲 |
| c. **原样保留** | 内容进产物（塞进 `detail`，或另开一个「节 map」字段） | 不丢内容；但塞进 `detail` 会**改变「详情＝作者写的考据」的语义**；**另开字段 ⇒ 又改产物字段集** |

**未定。** 演示的做法是**未知节 ⇒ 告警（`unknown-section`）并计数**，且**不改产物形状**。

## 8. 最小 Markdown 支持范围（**这条直接决定两端的活**）

### 8a. 两端现状（只读核对）

| 语法 | **Web 现状**（`web/app/render.js` `renderNotesBody` 的笔记子集） | **Android 现状** |
|---|---|---|
| 段落 / 行内换行 | ✅（段落 ＋ `<br>`） | ❌ 纯文本（`Text(notes)`） |
| 粗体 `**…**` | ✅ | ❌ |
| 斜体 `*…*` | ✅ | ❌ |
| 无序列表 `- ` / `* ` | ✅ | ❌ |
| 有序列表 `1. ` | ❌ 原样显示 | ❌ |
| 标题 `#`～`###` | ❌ 原样显示（`### 异文` 会变成一段写着 `### 异文` 的文字） | ❌ |
| 引用 `> ` | ❌ 原样显示 | ❌ |
| 行内代码 / 代码围栏 | ❌ 原样显示 | ❌ |
| 链接 `[文字](url)` | ❌ 原样显示 | ❌ |
| 表格 / 图片 / HTML | ❌ 原样显示 | ❌ |

⚠️ **最要紧的一句**：详情页现在是**结构化渲染**（两端都逐条渲染 `variants[].text` ＋ note，「底本与来源」标题**硬编码**），**不是**渲染一段 Markdown。若 `detail` 是 Markdown：

- **Web**：现有笔记子集**不含标题与引用**，而样例详情**正好用了 `### 小标题`＋列表** ⇒ **Web 也要扩子集**（至少补标题）。
- **Android**：**现在把正文/笔记当纯文本** ⇒ 需要**新增渲染能力**，而且是**从零到一**（新写一个最小 Markdown 渲染器：逐行解析 → Compose 段落 / `AnnotatedString` 行内样式）。

### 8b. 范围候选（哪几样进「最小支持范围」）

| 候选范围 | 含义 | 代价 |
|---|---|---|
| **只到「段落＋粗体」** | 最省 | 两端都最容易；但样例详情里的 `### 异文`／`### 分段依据` **要改写法**（不能再靠小标题分块），考据文本可读性下降 |
| **段落＋列表＋粗体＋标题（`###`）** | 够本材料样例用 | 两端各要加「标题」一项；表达力够写分块考据 |
| **＋引用 `> `** | 能写引文/校语 | 两端再加一项；样例里没用，属**未被行使**的能力 |
| **＋代码（行内与围栏）** | 能贴原文片段 | 两端都不便宜（围栏要状态机）；若 §6 选「不支持围栏」，则此项**必须排除** |
| **＋链接** | 能引出处 | Web/Android 都要加可点击处理；**离线优先**的应用里外链行为（是否打开浏览器、是否提示）**未定** |
| **＋有序列表 / 表格** | —— | 表格两端都很贵（Compose 无内置表格，需要自绘） |

- **范围到底含哪几样 —— 未定。** 演示在 `demo.mjs` 里**声明了一个候选范围**（`#`～`###` 标题、无序/有序列表、`> ` 引用、围栏、`---` 分隔线；行内粗体/斜体/代码/链接；**明确排除**表格/`####`+/图片/行首 HTML/脚注/任务列表），**只为让「超出范围的写法会响」可运行** —— **它不是已采纳范围**（`fixtures-ambiguous/ambiguous-detail.md` 里那些被报出来的表行与 `####`，就是「超出范围会响」的演示）。
- **两端必须一致**：项目约定「两端表现遵守同一约定」⇒ 同一段 `detail` 在 Web 与 Android 上**应当显示成同样的东西** ⇒ 需要一个**共享的「支持范围」定义** ＋ 两端的**对照测试**（Android 单测 ＋ Web e2e 各钉一份）。
- **代价随范围增长**：范围越大，两端实现 ＋ 测试 ＋ 以后每加一样语法的维护都越贵；范围越小，写考据时的表达力越弱。**这个取舍是待用户拍的。**
