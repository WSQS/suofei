# MD ↔ JSON 对照（本稿：源文件怎么写 ↔ 产物怎么装）

> **性质：待审材料，不是实施授权，也不是已采纳规格。**
> 下面每一份源 MD 都是**文件**（`samples/`、`fixtures-ambiguous/`），每一份产物 JSON 也都是**文件**（`json/`），并由 `demo.mjs` **逐字节比对**防手抄漂移（见 §6）。
> ⚠️ `json/*.json` 是**样例**，**不是**正式 `dist/content.json`，不参与发布。

## 2. 主线逐处对照（`real-01-with-detail.md` ↔ `real-01-with-detail.json`）

### 2.1 front matter → 每首诗的标量键

源文件（**本稿写法：没有 `dynastyOrder`、没有 `era`、没有 `variants`**）：

```yaml
id: gushi-shijiu-shou-01
title: "行行重行行"
author: "佚名"
dynasty: "汉"
genre: "五言古诗"
orderInSource: 1
source: "《文选》卷二十九·杂诗上「古诗一十九首」（李善注本）。电子文本：汉典古籍 gj.zdic.net/jibu/1224/34173.html，2026-10-14 访问；以四库全书本《六臣注文选》卷二十九对校。异文校记见 docs/sources/gushi-shijiu-shou.md。"
```

产物（**键序＝本稿草案键序**）：

```json
{
  "id": "gushi-shijiu-shou-01",
  "title": "行行重行行",
  "author": "佚名",
  "dynasty": "汉",
  "genre": "五言古诗",
  "source": "《文选》卷二十九·杂诗上「古诗一十九首」（李善注本）。…（原样）…",
  "orderInSource": 1,
  "detail": null,
  "stanzas": [ … ],
  "notes": null
}
```

逐项：

| 源里的写法 | 产物 | 说明 |
|---|---|---|
| `id: gushi-shijiu-shou-01` | `"id": "gushi-shijiu-shou-01"` | 与文件名一致（现契约）。**「归谁产生」未定** |
| `title: "行行重行行"` | `"title": "行行重行行"` | 引号是 YAML 的，进 JSON 变 JSON 字符串 |
| `dynasty: "汉"` | `"dynasty": "汉"` | **本稿变化**：源值一个中文串 → 产物**一个**键；不再有 `dynastyKey`/`dynastyLabel`/`dynastyOrder`。组序不在诗对象里（`top-level-dynasties.md`） |
| ~~`dynastyOrder: 100`~~ | —— | **源里不写、产物里没有**；组序由编译期按 `dynasty` 查表得到 |
| ~~`era: "东汉末"`~~ | —— | **已删**；源里再写 ⇒ 演示会响（`--parse fixtures-ambiguous/removed-keys.md` ⇒ EXIT=1） |
| `genre: "五言古诗"` | `"genre": "五言古诗"` | 保留（用户 2026-10-15） |
| `source: "…"` | `"source": "…"` | **案 A1**（本稿样例主线）；**案 A2** 时源里不写这个键、产物里也没有它（§4） |
| `orderInSource: 1` | `"orderInSource": 1` | 未改的「组内原次序」；整数 |
| ~~`variants: [ … ]`~~ | —— | **移除**；它的文字进 `## 详情` |

### 2.2 正文 → `stanzas`

```text
行行重行行，与君生别离。
相去万余里，各在天一涯。
道路阻且长，会面安可知？
胡马依北风，越鸟巢南枝。
相去日已远，衣带日已缓。
浮云蔽白日，游子不顾反。
思君令人老，岁月忽已晚。
弃捐勿复道，努力加餐饭。
```

```json
"stanzas": [
  [
    "行行重行行，与君生别离。",
    "相去万余里，各在天一涯。",
    "道路阻且长，会面安可知？",
    "胡马依北风，越鸟巢南枝。",
    "相去日已远，衣带日已缓。",
    "浮云蔽白日，游子不顾反。",
    "思君令人老，岁月忽已晚。",
    "弃捐勿复道，努力加餐饭。"
  ]
]
```

- **每印刷行一个字符串**；**空行＝段边界**（外层数组＝段）。真实《行行重行行》按底本通篇连排 ⇒ **单段**。
- 正文的**范围**由「第一个 `##`（不在围栏内）之前」这个**切分点**决定 ⇒ 切分规则本身**未定**（`undecided.md` §4）。

### 2.3 `## 详情` 整节 → `detail`（**一个字符串**）

源（`## 详情` 之后到文件末尾，内部只用 `###`）：

```markdown
## 详情

### 异文

- **游子不顾返** —— …
- **胡马嘶北风** —— …
- **会面安可期** —— …

### 分段依据

底本（…）通篇连排、篇内无空行 ⇒ 依底本不分段（本首正文＝单一 stanza）。
```

```json
"detail": "### 异文\n\n- **游子不顾返** —— …\n\n### 分段依据\n\n底本（…）通篇连排、篇内无空行 ⇒ 依底本不分段（本首正文＝单一 stanza）。"
```

要点：

- **节标题 `## 详情` 本身不进 `detail`**（它是边界，不是内容）；`detail` 从下一行开始。
- **`###` 原样保留**：编译器**不**把这些小节重新提取成结构字段（A 路线骨架：不重新提取）。
- 换行在 JSON 里是 `\n`；**连续空行、行尾空白**的处置**未定**（本演示只做 `trim()`）。
- 字段名 `detail` **只是草案**（候选见 `undecided.md` §2）。

### 2.4 `## 笔记` → `notes`

源（`## 笔记` 整节；无笔记时**这个节整段不存在**）：

```markdown
## 笔记

> ⚠️ 测试夹具：这段是测试夹具笔记，不是用户笔记；只用来验证「多行 Markdown 笔记」的编译路径，不代表任何真实用户内容。

- 夹具第一行：验证列表。
- 夹具第二行：验证同一段落里的**粗体**。

（夹具结束）
```

```json
"notes": "> ⚠️ 测试夹具：这段是测试夹具笔记，不是用户笔记；…\n\n- 夹具第一行：验证列表。\n- 夹具第二行：验证同一段落里的**粗体**。\n\n（夹具结束）"
```

⚠️ **笔记一律是明确标注的测试夹具**（`samples/real-01-no-detail.md`、`real-01-with-note.md` 里就写着「不是用户笔记」）。**不代用户写任何第一人称笔记**；真实数据 19 首的 `notes` 全是空。

## 3. 三种缺省：源里长什么样 ↔ 产物里怎么写

| 情况 | 样源文件 | 样产物 | `detail` | `notes` | `stanzas` |
|---|---|---|---|---|---|
| ① **只有原文**（详情、笔记都没有） | `real-01-text-only.md` | `json/real-01-text-only.json` | `null` | `null` | 8 行 / 单段 |
| ② **详情缺失**（有笔记、没有 `## 详情`） | `real-01-no-detail.md` | `json/real-01-no-detail.json` | `null` | （夹具文本） | 8 行 / 单段 |
| ③ **笔记缺失**（有 `## 详情`、没有 `## 笔记`） | `real-01-with-detail.md` | `json/real-01-with-detail.json` | （文本） | `null` | 8 行 / 单段 |
| ④ 都有（**只是补全对照**，不是缺省） | `real-01-with-note.md` | `json/real-01-with-note.json` | （文本） | （夹具文本） | 8 行 / 单段 |

写法差别就一句话：**缺的节在源文件里整段不存在**（文件里没有 `## 详情` 那一行，也没有 `## 笔记` 那一行）；产物里**当前写 `null`、不省略键**（契约 §2.2 的现行口径）。

⚠️ **「`null` 还是『键不存在』」本身是未定项**，两者对客户端含义不同（`null` ＝「明确知道没有」；缺键 ＝「不知道该有没有」），而且缺键会与字段集门的口径相冲 ⇒ `undecided.md` §3。

**未给样例、且不应出现的情况**：`stanzas` 为空（文件里连正文行都没有）。契约要求非空；**正文为空的产物形状没有定义**，本材料不给样例，也不把它当一种「缺省」。

## 4. 案 A2 对照（`source` 归入详情）

只有「来源文字住哪」不同，其余相同：

| | 案 A1（`real-01-*`） | 案 A2（`real-01-alt-source-in-detail.md`） |
|---|---|---|
| front matter | 有 `source: "…"` | **没有** `source:` |
| `## 详情` 第一节 | `### 异文` | `### 底本与来源`（来源文字变成详情里的一个小节） |
| 产物的 `source` 键 | 在 | **不在**（键路径少一条 ⇒ `fields.md` §4） |

**两案都给样例文件**（`samples/real-01-with-detail.md` 与 `samples/real-01-alt-source-in-detail.md`），**本材料不选**。

⚠️ 演示脚本对 A1/A2 **中立**：它的「演示最小必填键」里**不含** `source`（因为归属未定），所以两案样例都是 0 告警。

## 6. 产物形状的边界（这份 JSON 到哪一层为止）

- `json/*.json` **只到「每首诗对象」这一层**：它**不含** `formatVersion`／`contentVersion`／`generatedAt`／`dynasties`／`poems` 这层包装。
  **为什么**：顶层 `dynasties` 怎么处置、组序放哪，**用户没有逐字段确认** ⇒ 本稿只并列方案（`top-level-dynasties.md`），**不自行定**，因此也不给一份「看起来已定」的顶层产物。
- 顶层形状的**方案示意**另放在 `top-level-candidates/*.json`：每个文件都带一个 `_note` 字段写明「**方案示意，不是产物、不是 schema、不参与发布**」，**不是**可直接发布的产物。
- 生成与校验：`json/*.json` 由 `demo.mjs --print-json <名>` 打到 stdout（**脚本自己不写文件**，重定向由人做），随后 `demo.mjs` 每次运行都把它与解析结果**逐字节比对**（去掉 CRLF 与尾部空白后比较），不一致就在自检表里报「不一致←失败」。实际结果见 `demo-output.txt`。

## 7. 这份对照**没有**说什么

- 没有声称 `detail` 这个名字、`## 详情` 这个节名、它的切分规则或它的缺省语义已被采纳。
- 没有声称 `source` 留在字段（A1）或归详情（A2）已被采纳。
- 没有给「正文为空」「围栏未闭合」「重复 `## 详情`」等情形的**正式产物**（演示只对它们**告警 + 非零退出**，正式策略未定）。
- 没有行使**真实多段**（19 首真实内容都是单段）。
- 没有触碰 `content/`（真实 19 首一字未动）：上面所有源样例都是**拷贝/改写**到本目录里的样例，不是 `content/` 的文件。
