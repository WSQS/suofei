# A 路线：歧义与最小 Markdown 支持范围（逐条：现状 / 候选 / 未定）

> **性质：待审材料，不是实施授权。** 下面每条**都还没有结论**，候选**并列**、写明**代价**，本材料**不排推荐**。
> 唯一「已固定」的是 A 路线的骨架：**单文件自足** ＋ **`## 详情` 整节保留为一个 Markdown 文本字段**。**「分界怎么定、未知节怎么办、围栏算不算、客户端渲染哪些语法」全部未定。**
> 可运行部分见 `demo.mjs`：它对**未定/歧义构造**一律**计数 ＋ 告警 ＋（在 `--parse` 模式下）非零退出**，绝不静默。

---

## 1. `## 详情` 的分界：从哪起、到哪止？

**现状：未定。** `demo.mjs` 目前按**候选 1**实现 —— 但那只是「让告警可运行」的临时写法，**不是采纳**。

| 候选 | 分界规则 | 代价 / 风险 |
|---|---|---|
| **1. 到下一个任意 `## ` 止**（草案） | 从**第一个** `## 详情` 起，到**下一个以 `## ` 开头的行**（或文件末尾）为止 | 简单、规则最少；但**详情内部不能再出现 `##`**（只能用 `###` 及更深）；作者手滑写一个 `##` 就**提前断节**；第二个 `## 详情` 会被当成「另一个节」 |
| **2. 到下一个「已知具名节」止** | 到下一个已知名节（`## 笔记`）为止；**未知的 `## X` 行当作详情内容** | 未知节不会吞掉后面内容；但**拼写错误会静默变成详情文本**（例如 `## 詳情` 繁体、`## 详情 ` 多了空格），错误不再显形 |
| **3. 详情必须是最后一节（到 EOF）** | `## 详情` 之后**全部**归详情，直到文件末尾 | 详情内部**最自由**（可以有 `##`）；但**强制顺序**：`## 笔记` 不能跟在详情后面（要与现有样例顺序相反），且「详情 + 笔记」两节无法同时**都在详情之后** |
| **4. 显式结束标记** | `## 详情` … 到 `<!-- /详情 -->`（或 `## 详情结束`）为止 | 无歧义、详情内部可含 `##`；但**写作者要记住配对标记**，并给工程引入一种**新语法**（客户端与校验都要认） |
| **5. 围栏包裹** | `## 详情` 后接一个 ```md 围栏，详情＝围栏里的内容 | 切分天然清楚，且与「代码围栏」能力复用；但作者要多写一对围栏，「整节」的语义变成「围栏内容」，与「详情就是正文里的一节」的直觉有偏差 |

> **未定。** 本材料的样例（`samples/*.md`）**都不触发**这条歧义（详情内部只用 `###`），所以**无论选哪个候选，现有样例的产物都一样**；差异只在**详情内部出现 `##` 时**（`fixtures-ambiguous/ambiguous-detail.md` 就是在演示这种输入）。

## 2. 重复或未知的节怎么处置：报错 / 忽略 / 原样保留？

**现状：未定。** 演示脚本目前**只告警、不止损**（不静默丢内容，也不替你们决定怎么处理）。

### 2a. 出现**两个** `## 详情`

| 候选 | 行为 | 代价 |
|---|---|---|
| a. **报错**（编译失败） | 整份内容不产出，作者必须改 | 最安全、绝不丢内容；但**一个笔误就阻塞整批编译** |
| b. **后者覆盖前者** | 只留第二段 | **静默丢掉第一段**（考据内容损失，最危险） |
| c. **两段拼接** | 拼成一段 detail | 内容都在；但「拼」的语义（要不要加分隔、顺序）未定，且读者看不出这是两段 |
| d. **取第一个，其余告警并丢弃** | 用第一段，第二段只在告警里出现 | 产物可预测；但仍**丢内容**，只是「响了」 |

### 2b. 出现未知的 `## X`（如 `## 校本`）

| 候选 | 行为 | 代价 |
|---|---|---|
| a. **报错** | 编译失败 | 最安全；但**将来想加第三种节就得同时改编译器**（扩展性最差） |
| b. **忽略**（当它不存在） | 该节及其内容**消失** | 简单；但**静默丢内容** —— 与「宁可响、不许静默」这条纪律正面相冲 |
| c. **原样保留** | 内容进产物（塞进 `detail`，或另开一个「节 map」字段） | 不丢内容；但**塞进 `detail` 会改变「详情＝作者写的考据」的语义**；**另开字段 ⇒ 又改产物字段集 ⇒ 又要升版** |

> **未定。** 演示的做法是：**未知节 ⇒ 告警（`unknown-section`）并计数**，且**不改产物形状**（内容仍会落在 `detail` 里，因为 `## 校本` 之后的内容归入**下一个**已知节之前 —— 见 `../../history/round-2026-10-15-content-format-candidates/demo-output.txt` 里 `--parse` 的那次输出，可以看到 `detail` 只到围栏为止、`## 校本` 之后的内容**没有**进 `detail`）。**正式策略必须你们定，定之前不做正式实现。**

## 3. 围栏标题：正文里以 `#` 开头的行 / 代码围栏里的 `##`

**判据（说清楚「什么才算切分点」）：**

1. **切分点 ＝ 行首恰好是 `##` ＋ 一个空格**（`^##\s`）。
   - **`###` 不匹配**（它是详情内部的子标题，不是节边界）；
   - **单个 `#`**、**行中间的 `#`** 都不匹配（不构成切分点）。
2. **代码围栏内的行一律不是切分点** —— 识别前必须**先跟踪围栏状态**：行首出现 ` ``` ` 或 `~~~`（可带语言标注，如 ```md）＝ 开围栏；**同种符号**再次出现 ＝ 闭合。**围栏内部的 `## X` 是代码示例，不是节标题。**
3. **正文里以 `#` 开头的行**：因为它不匹配 `## `，**本来就不会被当切分点**；但它是**「诗行里混进了 Markdown 标题符」的污染信号** —— 现行 canary 明确要求「`stanzas` 里绝不出现以 `#` 开头的行」，所以**校验会响**。

| 候选（围栏支不支持） | 行为 | 代价 |
|---|---|---|
| **① 支持围栏**（演示按这个实现） | 跟踪围栏开闭，围栏内的 `##` 不当切分点 | 能写代码示例；但要有**状态机**，且**必须校验围栏成对闭合** —— 一个忘写的 ` ``` ` 会把**后面所有内容**都吃进围栏（静默吞节） |
| **② 不支持围栏** | 约定详情里**不写代码块**，出现 ` ``` ` 直接报错 | 实现最简单、无状态机；代价是**不能写代码示例**（对考据文本影响不大，但与「最小 Markdown 范围是否含代码」这条未定项联动：若不支持围栏，就不该把「代码」列进支持范围） |

> **未定。** 但**无论选哪个**，「围栏里的 `##` 算不算切分点」都是**必须显式回答**的问题 —— 演示因此对它**告警**（`fence-heading`）：本演示**不**把它当切分点，同时**大声报告**这里有一处需要你们决定的构造。

## 4. 最小 Markdown 支持范围：详情文本进产物后，客户端要渲染哪些语法？

**这一条越过了「源文件怎么写」，直接决定两端的活。**

### 4a. 两端现状（可核）

| 语法 | **Web 现状**（`web/app/render.js` `renderNotesBody` 的笔记渲染子集） | **Android 现状**（`android/.../ui/Screens.kt`） |
|---|---|---|
| 段落 / 行内换行 | ✅（段落 ＋ `<br>`） | ❌ 纯文本 |
| 粗体 `**…**` | ✅ | ❌ |
| 斜体 `*…*` | ✅ | ❌ |
| 无序列表 `- ` / `* ` | ✅ | ❌ |
| 有序列表 `1. ` | ❌ 原样显示 | ❌ |
| 标题 `#`～`###` | ❌ 原样显示（**`### 异文` 会变成一段写着 `### 异文` 的文字**） | ❌ |
| 引用 `> ` | ❌ 原样显示 | ❌ |
| 行内代码 / 代码围栏 | ❌ 原样显示 | ❌ |
| 链接 `[文字](url)` | ❌ 原样显示 | ❌ |
| 表格 / 图片 / HTML | ❌ 原样显示 | ❌ |

⚠️ **现状最要紧的一句**：**详情页现在是「结构化渲染」**（Web／Android 都逐条渲染 `variants[].text` ＋ note，标题「底本与来源」是**硬编码**的），**不是**渲染一段 Markdown。若详情改成 Markdown：
- **Web**：现有笔记子集**不含标题与引用**，而本材料的样例详情**正好用了 `### 小标题`＋列表** ⇒ **Web 也要扩子集**（至少补标题）。
- **Android**：**现在把笔记当纯文本**（`Text(poem.notes)`）⇒ 详情用 Markdown 意味着 **Android 需要新增渲染能力**，而且是**从零到一**：新写一个最小 Markdown 渲染器（逐行解析 → Compose 段落 / `AnnotatedString` 行内样式）。

### 4b. 范围候选（哪几样进「最小支持范围」）

| 候选范围 | 含义 | 代价 |
|---|---|---|
| **只到「段落＋粗体」** | 最省 | 两端都最容易；但样例详情里的 `### 异文`／`### 分段依据` **要改写法**（不能再靠小标题分块），考据文本的可读性下降 |
| **段落＋列表＋粗体＋标题（`###`）** | 够本材料样例用 | 两端各要加「标题」一项；表达力够写分块考据 |
| **＋引用 `> `** | 能写引文/校语 | 两端再加一项；样例里没用，属于**未被行使**的能力 |
| **＋代码（行内与围栏）** | 能贴原文片段 | 两端都不便宜（围栏要状态机）；若 §3 选「不支持围栏」，则此项**必须排除** |
| **＋链接** | 能引出处 | Web/Android 都要加可点击处理；**离线优先**的应用里外链行为（是否打开浏览器、是否提示）**未定** |
| **＋有序列表 / 表格** | —— | 表格两端都很贵（Compose 无内置表格，需要自绘） |

### 4c. 未定与代价总账

- **范围到底含哪几样 —— 未定。** 本材料在 `demo.mjs` 里**声明了一个候选范围**（`#`～`###` 标题、无序/有序列表、`> ` 引用、围栏、`---` 分隔线；行内粗体/斜体/代码/链接；**明确排除**表格/`####`+/图片/行首 HTML/脚注/任务列表），**只为让「超出范围的写法会响」可运行** —— 它**不是**已采纳范围（`fixtures-ambiguous/ambiguous-detail.md` 里那些被报出来的表行与 `####`，就是「超出范围会响」的演示）。
- **两端必须一致**：本项目约定「两端表现遵守同一约定」，所以同一段 `detail` 在 Web 与 Android 上**应当显示成同样的东西** ⇒ 需要一个**共享的「支持范围」定义** ＋ 两端的**对照测试**（Android 单测 ＋ Web e2e 各钉一份）。
- **代价随范围增长**：范围越大，两端实现 ＋ 测试 ＋ 以后每加一个字段的维护都越贵；范围越小，写考据时的表达力越弱。**这个取舍本身是待你们拍的。**
