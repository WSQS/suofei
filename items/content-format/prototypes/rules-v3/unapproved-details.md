# 未批准细则：**单一建议**（逐条 ＋ 理由 ＋ 「若你不同意会怎样」）

> **性质：材料，不是实施，也不是已采纳规则。**
> 规则 ④（固定分界）里这 5 件事**用户没有逐项批准**。本文**不并列一堆候选、不排「推荐」**，而是**每条给一个清楚的单一建议**；每条都写**理由**与**「若你不同意会怎样」**。
> `demo.mjs` 里按这些建议实现（**只为让「会响」可运行**，不是采纳）。

---

## 1. 未知节（如 `## 小结`）／重复节（两个 `## 详情`）

**建议：报错并响亮退出。** 编译失败、**不写产物**、非零退出，告警里点名**节名**与出现次数/位置。

- **未知节** = 顶层 `## ` 的**名字**不在 `{详情, 笔记}` 里。
- **重复节** = 同一个节名出现 ≥ 2 次。

**理由**

1. 这两种构造都会**静默丢内容**：重复节若「后者覆盖前者」，考据就永久消失（本项目已发生过「静默吞内容/污染」的事故，见 `AGENTS.md` 与 `../../item.md` 的硬约束）。
2. 项目已定原则：**宁可响，不许静默**。报错是唯一**既不丢内容、又机械可断言**的选项。
3. 代价可控：一个笔误只**阻塞**这一次编译（编译是本地、可立即重跑的动作），不会造成数据损失。

**若你不同意会怎样**：若改成「告警但继续」，就**必须**在同一处写清**产物以哪一节为准**，并接受随之的代价 ——
- 「后者覆盖」＝**静默丢**前面那一节（最危险）；
- 「拼接」＝读者看不出这是两段，且「要不要加分隔符」又变成新未定项；
- 「取第一个、其余丢弃」＝产物可预测，但**仍然丢内容**，只是响了。
并且这三种做法都会让「加第三种节」变成不需要改编译器，代价是**错误不再显形**（拼写错误如 `## 詳情` 繁体、`## 详情 ` 多空格会静默变成正文/详情文本）。

> 附注（也是**刻意接受的**扩展代价）：在「报错」案下，将来要加第三种节（如 `## 校本`）**必须同时改编译器与两端的节名清单**。这是为「错误必显形」付的价。

## 2. 代码围栏里的 `##` 算不算分界

**建议：先跟踪围栏状态，围栏内的 `##` 不算分界；同时「最小 Markdown 范围」不含围栏 ⇒ 一旦出现围栏行，该节判为越界并报错。**

两条一起说，才是完整的一条建议：

1. **分界判定必须先跟踪围栏**（行首 ` ``` ` / `~~~` 开闭配对）。围栏内的 `## xxx` **不是**分界点，绝不把围栏内部切成节。
2. 因为最小范围（§4）**不含**围栏，**任何围栏行本身**就是越界 ⇒ 报错；**未闭合的围栏**同样报错。

**理由**

1. 若不做第 1 条：一个未闭合的 ` ``` ` 会把**后面所有内容**吞进当前节（静默吞节）；而围栏里的 `##` 若被当分界，会把一句代码注释切成节标题 —— 两种都是**静默污染**。
2. 做了第 1 条、但若不报错，围栏就成了「合法但被特殊对待」的语法，范围定义与实现会不一致。
3. 结论：**围栏里的 `##` 不是分界，且整个围栏会响** —— 两件事合起来，围栏内容既**不会静默成为分界**，也**不会静默留在正文里**。

**若你不同意会怎样**：若你**想支持围栏**（允许在详情里贴代码示例），那么第 1 条答案**不变**（仍然不算分界），但要把围栏**加进最小范围** ⇒ 两端各加一个围栏状态机与渲染分支，且**未闭合围栏仍然必须是错误**（否则吞节问题回来）。换言之：只有「围栏在不在支持范围里」这一半可改，「围栏内不算分界」这一半不建议改。

## 3. 空节（`## 笔记` 下面什么都没有）

**建议：空节 = 缺失 ⇒ 产物写 `null`**（不是空字符串 `""`）。**空白节也算空节**（节体内只有空行/空白字符）。

**理由**

1. 规则 ③ 已定 `null` ＝「**明确知道没有**」；空节正是这种情况。
2. `""` 是**第四种状态**，且没有含义 —— 谁也说不清 `""` 与 `null` 在语义上差在哪。
3. UI「**缺省不显示**」的规则只需要判一次 `null`；若允许 `""`，两端每一处都得写 `x === null || x === ""`，**判空逻辑翻倍**，且容易漏。

**若你不同意会怎样**：若写 `""`，两端判空逻辑翻倍、`""`/`null` 的语义差别无人能说清；并且「字段集门」（键路径）会多出一种「有的诗是 `""`、有的是 `null`」的内容相关差异（同一个键两种值，门看不出，但客户端行为会分叉）。

## 4. 最小 Markdown 支持范围

**建议的最小集（明确、闭集）**

| 允许 | 写法 |
|---|---|
| 段落 | 连续非空行 = 一段 |
| 段内换行 | 段落里的一行 = 一次换行（`<br>` / 独立的行） |
| 无序列表 | 行首 `- ` |
| 有序列表 | 行首 `1. ` |
| 粗体 | 行内 `**…**` |
| 斜体 | 行内 `*…*` |
| 三级标题 | 行首 `### ` |
| 引用 | 行首 `> ` |

**明确排除（出现即报错）**：表格（`| … |`）、图片（`![]()`）、行首 HTML 标签、脚注（`[^…]`）、任务列表（`- [ ]`）、链接（`[文字](url)`）、行内代码与代码围栏（`` ` `` / ` ``` `）、`#` / `##` / `####` 及更深标题。

**理由**

1. 覆盖**现有材料**：本目录样例的详情正用 `### 异文` ＋ `- ` 列表；`###` 是详情分块的自然工具，少了它就得改写法、考据可读性下降。
2. 覆盖**考据文本的常见写法**：引用（`> `）用于引校语/引文。
3. 排除的都是「离线应用里**没有本地收益**或**代价很高**」的项：表格在 Compose 要**自绘**；链接的**外链行为**在离线优先的应用里未定（是否打开浏览器、是否提示）；代码与诗歌考据无关。
4. **闭集**（不是「至少支持这些」）才能让「越界会响」成立：范围一旦开口，「越界」就无法机械判定。

**两端代价（照实说，不是已完成的工作）**

- **Web（`web/app/render.js` `renderNotesBody` 的现有子集）**：现在支持 段落＋`<br>`＋无序列表＋行内粗体/斜体；**缺「三级标题」与「引用」** ⇒ **要扩子集**（至少补 `###`，因为样例详情正用它分块；引用 `> ` 随之补）。
- **Android（`android/.../ui/Screens.kt`）**：**现在没有任何 Markdown 渲染** —— 笔记是纯文本 `Text(notes)`，详情页是**结构化渲染**（逐条 `poem.source`、`poem.variants[].text/.note` ＋ 硬编码小标题）。若 `detail` 变成一段 Markdown，Android **要从零新增渲染能力**：逐行解析 → Compose 段落/列表/标题 ＋ `AnnotatedString` 行内样式。
- **两端必须一致**：项目约定「两端表现遵守同一约定」⇒ 这份范围要**两端共用一份定义** ＋ **对照测试**（Android 单测 ＋ Web e2e 各钉一份）。

**若你不同意会怎样**：每多一样语法，**两端各加实现 ＋ 测试**，且范围定义必须由两端共用（否则两端会漂）。范围越小，写考据时就只能用「段落＋列表＋粗体＋引用＋`###`」；范围越大（尤其**表格、链接、代码**），两端越贵 —— 表格要自绘、链接要定离线外链行为、代码要引入围栏状态机（与 §2 联动）。

## 5.（附）这 5 条建议**不改变**已定 4 条

- 未知节/重复节报错、空节＝`null`、最小范围 —— 都不改变规则 ①②③④ 的产物**键**与**键序**；它们只决定「什么样的源算合法」与「同一个键的值是 `null` 还是字符串」。
- 若这些建议被采纳，「字段集」本身**不因为这几条**而变化（仍是 `rules-v3.md §1/§2` 那两组键）。
