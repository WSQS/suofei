# 源字段 vs 产物派生字段（**新规则下**的分工）

> **性质：材料，不是实施。** 本文说清：**作者在 MD 里写什么**（源字段）／**编译期算出什么**（派生字段），以及
> **`dynasty`（中文单值）与顶层 `dynasties`（中文数组）的分工**。

---

## 1. 一览：谁写、谁算

| 位置 | 键 | 归类 | 说明 |
|---|---|---|---|
| front matter | `title` | **源** | 作者写 |
| front matter | `author` | **源** | 作者写（佚名/未知照写，不编造人名） |
| front matter | `dynasty` | **源** | 作者写**一个中文朝代名**（如 `汉`） |
| front matter | `genre` | **源** | 作者写（可缺 ⇒ `null`） |
| front matter | `orderInSource` | **源** | 作者写底本原次序（可缺 ⇒ `null`） |
| front matter | `source` | **源** | 作者写底本/来源 |
| **文件名** | `id` | **派生** | **文件名去 `.md`**（规则 ②）；源里**不写** `id` |
| 正文（原文） | `stanzas` | **派生** | 由正文按**空行**分段得出（段的数组、每段是行的数组） |
| `## 详情` 节 | `detail` | **派生** | 节正文；缺节/空节 ⇒ `null` |
| `## 笔记` 节 | `notes` | **派生** | 节正文；缺节/空节 ⇒ `null` |
| 顶层 | `dynasties` | **派生** | **编译期产出的有序中文朝代名数组**（规则 ①） |
| 顶层 | `formatVersion`／`contentVersion`／`generatedAt` | **派生** | 编译期产出（版本/时间） |

**一句话**：源 MD 提供**身份与文本**（title/author/dynasty/genre/orderInSource/source ＋ 原文 ＋ 两个节的正文）；编译期把它们**切分、分段、排序**成产物的键。

## 2. `dynasty`（中文单值）与顶层 `dynasties`（中文数组）的**分工**

| | 每首诗的 `dynasty` | 顶层的 `dynasties` |
|---|---|---|
| 形状 | **字符串**（中文单值），如 `"汉"` | **字符串数组**（有序），如 `["汉"]` |
| 谁产出 | 作者写在 front matter | **编译期派生**（不是作者手写） |
| 表达什么 | 这首诗**属于哪个朝代**（身份） | **有哪些组** ＋ **组的渲染次序**（次序权威） |
| 客户端怎么用 | 拿它去匹配某个组 | **照数组的次序**渲染组；**不得**从 `poems` 首次出现顺序反推 |
| 组内次序 | 无关（`dynasty` 不携带次序） | 无关；组内次序由 `orderInSource` 决定 |

**分工一句话**：**源携带身份，顶层数组携带「有哪些组」与「组的次序」。**

**编译期怎么把单值映射成有序数组**：编译工具内部持有一张**朝代次序表**（登记中文名 → 整数 order，例：先秦 0／汉 100／魏晋 200／…／未详 9999）。
编译时：

1. 收集所有诗中出现的 `dynasty`（只保留**实际有内容**的组，空组不出现）；
2. 按表里的 order **升序**排好；
3. 输出**中文名数组**（不输出 `key`/`label`/`order` 子字段）。

⇒ 因此要求：**每个被使用的 `dynasty` 值必须在表里能查到次序**；查不到就**报错**（演示口径 `undeclared-dynasty`，正式口径见契约 §1.3 `DYNASTY_UNDECLARED`）。

**没有稳定的 ASCII 键了**：新规则下顶层 `dynasties` 是**中文值数组**，`{key: "han", label: "汉", order: 100}` 这种三家形状**退出产物**。这也意味着「分组身份」＝**中文名本身**（改一个字＝改身份），且 `key` 只活在工具内部。这是**如实的变化**，不是遗漏。

**与已定规则不冲突**：目录组织（`rules-v3.md §7`）**不提供** `dynasty`，也不提供次序 —— 朝代仍只由 front matter `dynasty` 决定，次序仍只由顶层数组决定。

## 3. 一处**仍未被用户拍板**的技术选择（如实列出，不藏）

| 变体 | 产物 `dynasty` 从哪来 | 归类 |
|---|---|---|
| **甲 · 透传** | 源文件 `dynasty:` 原样写进产物（表只用来校验 ＋ 求次序） | 源字段 |
| **乙 · 规范化** | 源值必须命中表，产物写**表里的中文名** | 派生快照 |

当前 19 首的源值**恰好都等于表里的 `汉`** ⇒ 两变体**输出完全相同**；差异只在**边界输入**（别名/空白/异体）时显形。本材料**不替用户选**，但**建议**：取**乙（规范化）**——因为它让「组身份」只有一个权威（表），并且让「值必须在表里」这条校验有意义（甲之下，源值写错别名会被原样透传进产物，客户端就会多出一个「查不到次序」的组）。**若你不同意**（要甲）：则必须接受**源值即身份**，别名/空白差异由作者负责，注册表只当「认不认识」的判据。

## 4. 与 `formatVersion=1` 的差别（派生字段的变化，只列一次）

| | `formatVersion=1`（现状） | 本稿（rules-v3） |
|---|---|---|
| 顶层 `dynasties` | `[{key,label,order}]` | **`["汉"]`（中文名数组）** |
| 每首朝代 | `dynastyKey`＋`dynastyLabel`＋`dynastyOrder` 三份 | **一个 `dynasty`（中文单值）** |
| 每首 `era` | 有 | **无** |
| 每首 `variants[]` | 有 | **无**（考据改住 `detail` 文本） |
| 每首 `detail` | 无 | **有**（Markdown 文本，可 `null`） |
| `id` 来源 | front matter 手填（要求 ＝ 文件名） | **文件名派生**（源里不写） |

⇒ 字段集变过 ⇒ 按已定 B 规则，一旦采纳实施，`formatVersion` **必须升**（`rules-v3.md §6`，只提一次）。
