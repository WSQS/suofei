## 2. 逐块：两端预期效果

### 2.1 front matter（第 1–8 行）

- **源**：`title` / `author` / `dynasty` / `genre` / `orderInSource` / `source`（必填四项；**不写** `id`、`era`、`dynastyOrder`、`variants`）。
- **产物**：六个键 ＋ 由路径派生的 `id`。**这一块不渲染成任何界面元素**，但它决定题头与目录分组。
- **Web 预期**：
  - 现状：诗页题下一行由 `poem.dynastyLabel` / `poem.author` / `poem.era` / `poem.genre` 拼成（`web/app/render.js:295`）；目录分组按 `poem.dynastyKey` 归组、组名取 `poem.dynastyLabel`（`web/app/render.js:90-116`、`264-267`）；产物校验要求这些键是字符串（`web/app/content.js:65-75`）。
  - 要改：题下一行改成 `dynasty · author · genre`（`genre` 为 `null` 时按现有 `filter(Boolean)` 自动省略）；分组改成按 `poem.dynasty` 匹配顶层 `dynasties` 里的**中文名**；`content.js` 的校验同步（`dynasties` 元素从对象变字符串）。
- **Android 预期**：
  - 现状：题下一行同样用 `dynastyLabel` / `era`（`android/app/src/main/java/dev/sopho/suofei/ui/ScreenContent.kt:19-20`）；解析要求 `dynastyKey` / `dynastyLabel` / `dynastyOrder` 三个键且 `dynastyKey` 必须在 `dynasties` 里声明（`…/data/ContentParser.kt:62-75`）；`Dynasty(key,label,order)`（`…/data/Domain.kt:10`）；分组 `sortedBy { it.dynasty.order }`（`…/data/Domain.kt:49-60`）。
  - 要改：`Poem` 去掉 dynastyKey/dynastyLabel/dynastyOrder/era、加 `dynasty: String`；`Dynasty` 只要中文 label；解析按字符串数组读、按中文名分组与排序（次序照顶层数组）。
- **两端共同的预期效果**：题头与目录**看起来不变**（仍是「汉」这一组、仍是同一句题头），变的是**数据来源**（从「每首自带 key/label/order」变成「顶层有序中文数组 ＋ 每首一个中文值」）。

### 2.2 原文（第 10–17 行）

- **源**：每印刷行一行；**空行＝分段**。本首底本连排 ⇒ 8 行组成**单一段**。
- **产物**：`stanzas` = `[["行行重行行，与君生别离。", …, "弃捐勿复道，努力加餐饭。"]]`。
- **Web 预期**：现状已实现——每段一个 `<section class="stanza">`、每行一个 `<p class="line">`（`web/app/render.js:203-228`）⇒ **不改**。
- **Android 预期**：现状已实现——每段一个 Column（段间 Spacer）、段内每行一个 `Text`（`…/ui/Screens.kt:270-278`）⇒ **不改**。
- **要点（两端都要钉住）**：**正文不走 Markdown**。诗行里的 `**`、`#`、`- ` 一律原样显示，两端都不得当语法渲染（合成检查里有一条「原文里的 `**` 不是粗体 ⇒ 无诊断、诗行原样保留」在跑）。

### 2.3 `## 详情` 节（第 19–30 行）

- **源**：`## 详情` 之后到下一个 `## ` 或 EOF；内容是 Markdown 文本（本样例用到 `### `／`- `／`**粗体**`／段落）。
- **产物**：`detail` ＝ 整段字符串（本稿建议：**不再**拆成 `variants[]` 那样的结构化字段；考据文本整段保留、详情页整段渲染）。
- **Web 预期**：
  - 现状：详情页渲染的是**结构化**数据（`poem.source` ＋ 逐条 `poem.variants[].text/.note`，`web/app/render.js:335-380`）；笔记用的最小渲染器只认**段落／`<br>`／`- `(或 `* `)／粗体／斜体**（`web/app/render.js:149-201`）⇒ `### ` 与 `> ` **会落进段落、把 `### 异文` 字面显示出来**。
  - 要改：详情页改成渲染 `poem.detail` 这段文本，并**给渲染器补两样**（行首 `### `＝小标题、行首 `> `＝引用块）。本样例的详情正依赖 `### 异文` / `### 分段依据` 分块。
- **Android 预期**：
  - 现状：详情页是**结构化**渲染（硬编码「底本与来源」「异文」两个小标题 ＋ 逐条 `variants`，`…/ui/Screens.kt:339-380`）；**整个 Android 端没有任何 Markdown 渲染**（笔记也是纯 `Text`）。
  - 要改：**从零新增最小 Markdown 渲染**（逐行 → Compose 块：段落／无序列表／有序列表／三级标题／引用；行内 → `AnnotatedString` 的 `SpanStyle` 做粗体/斜体），详情页改渲染 `detail` 整段。**这是两端里工作量最大的一处**。
- **两端共同的预期效果**：读者在详情页看到的是同一份文本：三个小标题分块 ＋ 每条异文一个列表项（开头加粗的异文词）＋「分段依据」一段话。

### 2.4 `## 笔记` 节（第 31–32 行，**空节**）

- **源**：`## 笔记` 下面什么都没有 ⇒ **空节 = 缺失**（本稿建议）。
- **产物**：`"notes": null`，**键保留**（不写 `""`、不删键）。
- **Web 预期**：
  - 现状：`hasNotes()` 判「非空字符串」（`web/app/render.js:128-130`）；有笔记时 `<details>` 折叠 ＋ 最小渲染（`298-303`）；**没有笔记时现在渲染一句「这首诗还没有笔记（未记录）。」**（`web/app/render.js:305-311`）。
  - 要改：与已定规则 ③「无笔记时隐藏整个笔记区」对齐 ⇒ **那一句空状态文案要撤掉**（整块 notes 区不出现）。这是**现状与已定规则不一致**，不是新增功能。
- **Android 预期**：
  - 现状：有一个「笔记」折叠按钮，展开后 `Text(poem.notes ?: "（无笔记）")`，**纯文本**（`…/ui/Screens.kt:281-320`）；没有笔记时**按钮照旧显示**。
  - 要改：notes 为 `null` 时**连折叠入口一起不出现**；有笔记时用与详情同一套最小渲染。
- **两端共同的预期效果**：这一首**没有笔记 → 笔记区在两个端上都不出现**（不显示 `null`、也不显示「还没有笔记」）。

## 4. 两端现状 vs 要改（一张表）

| 块 | Web 现状 | Web 要改 | Android 现状 | Android 要改 |
|---|---|---|---|---|
| front matter | 用 `dynastyLabel`/`era`/`dynastyKey` | 改用 `dynasty` ＋ 顶层中文数组 | 同上（另有 `dynastyOrder`） | 同 Web ＋ 去掉每首自带 order |
| 原文 | 已实现（段/行） | 不改（但要断言「正文不走 Markdown」） | 已实现（段/行） | 不改（同一条断言） |
| `## 详情` | 结构化渲染 `source`＋`variants`；渲染器缺 `### `／`> ` | 渲染 `detail` 文本 ＋ 补 `### `／`> ` 两样 | 结构化渲染（硬编码小标题）＋**零 Markdown** | **从零新增** Markdown 渲染 ＋ 改渲染 `detail` |
| `## 笔记` | 有笔记走 `details`＋最小渲染；**无笔记显示一句空状态** | 与规则 ③ 对齐（整块隐藏）＋补齐 `### `／`> ` | 折叠按钮＋纯 `Text`；无笔记仍显示按钮 | 整块隐藏 ＋ 新增 Markdown 渲染 |

原文里那两处 `### `（`### 异文` / `### 分段依据`）是**必补**项：少了它，Web 端会把 `### ` 字面画给读者看。

## 5. 这一页里哪些是「已定」、哪些是「我建议的」

- **已定（照写，不再问）**：源格式三段固定分界；`## 详情`／`## 笔记` 是两个节、缺节可省；`notes`／`detail` 缺失写 `null`；
  顶层有序中文朝代数组；`id` 由路径派生；每首 10 键（`id,title,author,dynasty,genre,source,orderInSource,detail,stanzas,notes` —— 注意**源字段与产物键不同名同数**：源里没有 `id`／`detail`／`stanzas`／`notes`）。
- **我建议的（本稿要你拍板）**：最小 Markdown 闭集（8 样）；四条细则（未知节/重复节/空节/围栏）；组名精确匹配且不做别名。见另外三页。
- **不是本项目待做工作**：上面每一处「要改」都**还没做**（本稿没改任何生产代码）；它们是**代价陈述**，供排期与验收用。
