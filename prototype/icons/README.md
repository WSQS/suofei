## 画布与尺寸约定（为什么这么画）

- Android adaptive icon：**108×108dp 画布**；系统**保证可见**的是中心**内接 72×72 方**，外侧 18dp 可能被遮罩吃掉；
  启动器还可能再缩放（通知栏/设置里图标更小）。
- 本原型把**前景内容全部控制在中心直径 66 的圆内** —— 比 72 方更保守，任何遮罩都不会切到笔画。
- 背景层**满幅**（`bg` 铺满 108），前景层只放符号。
- 另外给了 **mono（单色层）**：Android 13+ 的「主题图标」会用它按系统取色重绘 ⇒ 只用 alpha 表达层级，不用颜色。
- **minSdk 26 ⇒ 只需 adaptive icon（`mipmap-anydpi-v26` + 矢量），不需要 legacy 位图 mipmap**。这也意味着图标必须是**矢量**（本目录给的就是 SVG）。

## 四个方向

| 方向 | 想法 | 代价（我如实写） |
|---|---|---|
| **A · 单字「索」＋ accent 发丝下划线** | 最直白：一个字读得出名字。下划线复用「组名左沿发丝线」的记号（转向 90°） | 字形小尺寸下笔画多；不同 ROM 的无衬线体不同 ⇒ 字形会有微差（见下面「工程约束」） |
| **B · 发丝诗行（无字）** | 只用「诗行」这张图：四条发丝线，其中一条是 accent —— 像读到某一行。抽象、任何尺寸都成立，最贴合「结构感」 | 不体现应用名；阅读类应用图标可能撞脸 |
| **C · 「[索]」括号记号** | 直接用这套视觉自己的记号（目录里计数写作 `[3] 首`），把它套在字上 | ⚠️ **三个字符并排，横向就顶到 66 安全区上限 ⇒ 48px 下「索」糊**（预览图里 48px 一列可证）。我不推荐它，但按实拍留档 |
| **D · 「[19]」计数记号** | 用这套视觉的计数记号，数字＝《古诗十九首》的 19；等宽数字细且不糊 | 读不到应用名；`19` 是我们自己的梗，别人未必懂（对个人诗集应用可能正好） |

## 一条必须传下去的工程约束（否则「原型好看、装上变样」）

**A / C / D 三个方向用的是「字」**，而 SVG 里的字是**靠字体**排出来的：
Windows 上排出来的是 Microsoft YaHei UI，**Android 上根本不会有这个字体** ⇒ 照 SVG 直接实现会得到**另一个字形**。

所以：**一旦用户选了 A/C/D 这类字形方向，落地时必须把字形转成路径（outline/矢量轮廓），不能依赖运行时的系统字体**——
否则又是「评审过的东西没接线到实现」。B 方向没有这个问题（纯矩形）。
（对照：`visual-tokens.md` 里「Android 没有宋体」的结论说的是**正文**；图标这边的问题不是衬线/无衬线，而是**字体是否存在**。）

⇒ 第二轮只做两件事：**字体探索**（第二轮 ①）与**把 C 里最糊的括号改掉**（第二轮 ②）。

## 第二轮：字体是怎么选的（这里有一个比「好看」更硬的分野）

图标**不能依赖运行时字体**——Android 上没有微软雅黑，我们也不能把字体文件塞进产物而不顾授权。所以字形只有两条路：

| 落地方式 | 对字体的要求 | 适用 |
|---|---|---|
| **转矢量轮廓**（推荐：矢量、任意尺寸都锐） | 字体必须**可自由使用**（OFL 等），其轮廓可嵌入 | 本机已装的 **`Noto Sans SC`／`Noto Serif SC`**（SIL OFL 1.1，思源黑体/宋体同源） |
| **烘成位图 mipmap**（PNG） | 专有字体（微软雅黑/等线/楷体/华文系）**只建议走这条** | 上面两行之外的字体 |

所以第二轮的表把「**可矢量？**」单独列为一列——**这是选字体时真正的分野**，不只是好看不好看。

**自检（给「看起来有区别」上保险）**：表右侧一列是页面内实测的 ① `document.fonts.check` 是否找得到该字体、② 把「索」画进 canvas 取像素算出的**字形指纹**。**两行指纹相同＝两者渲染成了同一个形状**，说明有个字体名没生效、悄悄退回了默认字体。本次实测 **8 个字体指纹两两不同**（`a3d16d69` / `c42774bd` / `b76f9125` / `82286f59` / `1ddef235` / `2affefad` / `4532b386` / `acfa3110`）⇒ 不存在「名字写错、画面看起来一样」这种假结果。
（顺带：CJK 字形的宽度恒等于字号（em 方块），所以「量字宽」在这里**没有区分力**，我没用它。）

## 第二轮的结论排序（我自己的观察，供你否决）

1. **`Noto Sans SC`（OFL）—— 首选**：与令牌「全部无衬线」完全一致，且**可转矢量**（零授权风险），48px 下仍清楚。
2. **`Noto Serif SC`（OFL）—— 若你要「书卷气」**：它是唯一一个「宋体 + 可矢量」的选项；代价是**与令牌「全无衬线」不一致** —— 图标算不算这个令牌的例外，得你定。
3. **`SimHei 黑体`**：48px 下**最清楚**（笔画最粗），但只能用位图，且观感偏老。
4. 楷体系（`KaiTi` / `STKaiti`）最「古诗」，但**笔画有粗细变化 ⇒ 小尺寸最糊**，且只能位图。
5. `STSong`：横画细，**48px 下横画最容易整条消失**（看最后一列就是证据）。

## C 的括号怎么修的（第二轮 ②）

第一轮的 C **借用了字体里的 `[` `]` 字形**，三个字符并排就顶到安全区上限 ⇒ 48px 糊。第二轮把括号**改成自绘发丝线**（左右两条 2.5px 竖线 + 四段短横、角部断开），并给三种排布：

| 变体 | 做法 |
|---|---|
| C0 | 字体括号（第一轮原样，留作对照） |
| C1 | 发丝方括号，括号色 `text-faint` |
| C2 | 发丝方括号，括号色 `accent-line`（弱化，让字更突出） |
| C3 | 换掉括号：左沿一条 accent 发丝竖线 ＋ 索 |

## 诚实边界（这一轮**没有**做的）

- 只出了 **SVG 源 + PNG 预览**；**没有**生成 Android 的 `vector drawable`（XML）、没有改 `android/` 任何文件 —— 那属另一写入范围，等用户定方向。
- **没有在真实启动器/真机上看过**：预览里的遮罩是 CSS 近似（`border-radius`），真实遮罩形状随厂商与系统版本不同；mono 层的实际效果依赖系统的「主题图标」开关（Android 13+）。
- **没有**做 Play Store 512×512（本项目不发 Play，只有 GitHub Release 的 APK 与 Pages 站点）。
- 预览由无头 Chromium 出图：它渲染的是**桌面字体**，图上看到的字与手机上会有差异（这正是上一条约束的由来）。
