索斐 · 图标第四轮：A / C 各留一个基线，另出五个新形态

按你的话：第二轮那些变体不铺开了（A 与 C 各留**一个代表**作基线），另设计**五个新形态** —— 都还在「字＋一处结构记号」这一族里，但记号的位置与形态是新的。
尺寸这一列要看全：图标是**两端都用**的——Android 启动图标至少 48px，而 Web favicon 会小到 32 与 16。32/16 两列就是「这个形态在 favicon 上还成不成立」的答案。
字形是从 Noto Sans SC（OFL）抽出的**矢量轮廓**，本页所有图标产物都不含 <text>（脚本里是硬断言）。

A · 单字「索」＋ accent 下划线基线第一轮保留项。一个字读得出名字；下划线复用「组名左沿发丝线」的记号（转向 90°）。代价：字最大最清楚；记号只有一条线，「容器/记号」感最弱。
C · 字 ＋ 发丝方括号基线第一轮保留项（括号已按第二轮改成自绘发丝线）。把目录里「[3] 首」那套计数记号套在字上。代价：记号感最强；但括号占横向空间 ⇒ **字要缩小约 14%**（这就是下面 N3 要修的那点）。
N1 · 字 ＋ 右下角一条 accent 角标新记号缩到最小（一条 18px 的短发丝），把省下的空间全给字：**字与 A 一样大（42）**，而右下那个「角标」给出方向感与未完成感。代价：角标很小 ⇒ 远看基本等于「只有字」；识别全靠字形本身。
N2 · 字 ＋ L 形半框（左沿＋底沿）新只用两条发丝线构成一个「L」：左边一条竖线（＝组名左沿那套记号）＋ 底边一条横线。像一个引文块的起手，**不对称**，不像 C 那样把字关进箱子。代价：不对称 ⇒ 在圆形遮罩里重心偏左下，需要对位；小尺寸下 L 的两条线可能只剩一条。
N3 · 收紧的发丝方括号（正面修 C 的缺点）新同一个「括号」念头，但把括号**贴着字**收窄：于是字能放大到 **42（＝A 的大小）**，括号只比字高一点点。既保住记号，又不牺牲清晰度。代价：括号与字之间只有约 3px 缝 ⇒ 小尺寸下可能和笔画粘在一起（这正是它要冒的险，看 32/16 两列）。
N4 · A ＋ 极淡网格底（令牌里的 `bg-pattern`）新（诚实实验）把原型里那层「1px 极淡网格」放进图标（`rgba(255,255,255,0.028)`，与令牌逐字一致），看它能不能替我们表达「终端感」。代价：⚠️ **实测结论：几乎看不见** —— 该值本就是为了「极淡」，在图标尺寸下它既加不了结构感、又增加了杂点。⇒ 想用它只能**偏离令牌调浓**，那是另一件事（要你另外拍板）。
N5 · 字 ＋ 上下两条发丝（引文块）新打开 C 的左右两边，只留下**上下两条**（与字同宽的细线），像引文的起止线／书页的天头地脚。结构感来自「夹住」，而不来自「关住」。代价：上下线在小尺寸会先糊成两条灰边；且与 A 一样不提供横向边界。
