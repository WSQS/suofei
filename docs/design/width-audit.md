## 0 测的是什么口径、怎么测的

**被测口径**（用户 2026-10-15 选定、2026-10-16 复核；＝采纳锚原文）：

> `C = min(V, max(320, 0.88 × (V − 24)))`，`V`＝视口宽；`24` 是**从视口宽一次性扣除的总量**（**不是左右各 12**）；

**怎么加载**：**真实应用，不是原型页** —— 用 `web/scripts/lib/deploy.mjs` 的 `makeDeployment()` 组一个真实部署目录

**8 个视口与采纳锚同一组**（同高、同 `mobile` 标记，这样每一行都能与锚的目录页/诗页数字并排看）：
320×568 / 360×932 / 390×844 / 412×915 / 430×932 / 740×360 / 834×1112 / 1180×900。

**量法**：元素**墨迹**用 `Range` 逐**视觉行盒**量（同一行上的多个片段——`<strong>` 等内联元素——按 `top` 合并，

## 8 能读出来的结论（每条都能在表里对照）

1. **关于页与详情页都遵守已选口径，且与采纳锚逐档吻合**：`C` 实测 = 公式（Δ ≤ 0.0144px，1/64px 舍入）；
   列外余白 = `(V−C)/2`（320 上是 0）；行内沿 16.8px 照旧；正文可用宽 = `C−33.6`。
2. **两页都没有横向溢出**（8 档全部 `scrollWidth === innerWidth`，`visualViewport.width` 也等于目标宽）——
   也就是说「320 上仓库链接顶边」这个担心，**在当前内容与实际排布下没有发生**。
3. **最容易顶边的是等宽 URL 的长度，不是容器宽度**：等宽步进 7.7031px/字符 ⇒ 320/360 上 **37 字符是单行上限**，
   38 字符起折行；**折行而不溢出**（`overflow-wrap: anywhere`）。这是「URL 变长」时的真实边界，供负责人在
   改关于页（仓库链接改回 `<a>`）时一并判断要不要给长 URL 别的策略。
4. **详情正文**在 8 档上都没越界；列表项左沿 1.3rem、小标题/段落贴内容左沿；最长行的余量 2.57px（320）→ 3.56px（1180）。
5. ⚠ 本机字体（`Consolas` / `Microsoft YaHei UI`）会改「231.094px」「263.031px」这类**长度**数字
   ⇒ 折行判据要重算（与采纳锚「最长一行 213.19px」同一注意项）；本报告的数字是**本机无头 Chromium** 下的。
