# 新增诗作的录入与核对流程（现格式 `formatVersion: 2`）

> 用途：用户之后给「下一批诗」时，照这份做——**不需要先改代码**（多朝代已就绪，见 §5/§6）。
> 本文只写**怎么录、怎么核、哪里有坑**；内容本身的取舍（选哪些诗、底本、异文）由内容线定。
>
> ⚠ **现状（2026-10-16）**：用户已选定**第一首**（毛《七律·和郭沫若同志》）；人类问题 `q-2fa8c3a3`
> **已关**（用户在普通消息里选定，out-of-band 已答）⇒ **不必再等清单**。但该作品**不是公版**
> （权利分析见 `docs/sources/mao-he-guo-moruo-intake.md`）：**权利门未过之前，不把正文写进 `content/`**，
> 也不抄**全文/现代译注**（本流程只准备“怎么录”，不代替版权判定）。

## 1 文件与命名：ID 从路径派生

- 路径：`content/poems/<集合名>/<题名>.md`（现库：`content/poems/古诗十九首/<题名>.md`）。
- **ID ＝ 相对 `content/poems/` 的完整相对路径、去掉 `.md`、把 `/` 写成 `-`**；再做 **NFC 归一**。
  例：`古诗十九首/行行重行行.md` ⇒ id `古诗十九首-行行重行行`。
- 允许根下直接放文件，也允许多层目录；**层级由人定，ID 跟着变**（改了层级＝改了 ID）。
- **判重**：`NFC + 大小写折叠`后相同即视为同一个 ID，报 `ID_DUPLICATE` 并**逐条列出冲突路径**。
- ⚠ **真陷阱**：题名里**本身带 `-`** 会与「路径拼出来的 `-`」撞车（`A/B-C.md` 与 `A-B/C.md` 折叠后相同）。
  含连字符的题名请先想清楚层级，别靠运气。

## 2 front matter（现格式；**不要再写 v1 的键**）

| 键 | 必填 | 规则 |
|---|---|---|
| `title` | ✔ | 显示用题名 |
| `author` | ✔ | 字符串。「佚名/无名氏/阙名/未知/未详/不详」这批标记见 `schema/unknown-authors.json`（排序与展示共用同一批） |
| `dynasty` | ✔ | **必须逐字符等于**注册表里的中文 label（`tools/lib/dynasties.mjs`）：先秦／汉／魏晋／南北朝／唐／宋／元／明／清／近现代／未详。**精确匹配、不 trim、不做别名**（「东汉」不会静默归到「汉」，未声明的 label 直接报 `DYNASTY_UNDECLARED`） |
| `source` | ✔ | 底本与来源正文（详情页顶部那段） |
| `genre` | — | 自由字符串（如 `五言古诗`），只做类型校验，无注册表 |
| `orderInSource` | — | 底本原次序：**≥1 的整数**，**组内**次序；不写不报错 |

⚠ v1 的 `id` / `dynastyOrder` / `dynastyKey` / `dynastyLabel` / `era` / `variants` / `authorSortKey` / `titleSortKey`
**一个都不要写**：编译器会报「新格式已去掉源字段」而且**不静默转换**（要保留的考据搬进 `## 详情`）。

## 3 正文与节

- **正文区 ＝ 原文**：**空行＝分段**（产物里的 `stanzas`）；一行＝一个印刷行（窄屏的视觉折行是显示层的事，不改数据）。
- `## 详情`：考据／来源／异文。内容是**最小 Markdown 闭集**：
  段落／段内换行／`- ` 无序列表／`1. ` 有序列表／`**粗体**`／`*斜体*`／`### ` 三级标题／`> ` 引用。
  **表格、行内代码、图片、链接、代码围栏、`# ` 与 `#### `、任务列表、脚注、行首 HTML 一律报错**
  （闭集之外出现即错，不会静默降级）；块标记必须**行首第 0 列 ＋ 恰好一个空格 ＋ 其后非空白**。
- `## 笔记`：用户个人笔记（**不代用户创作**）。
- **空节 ⇒ 值写 `null`、键仍在**（不是删键、也不是 `""`；空白节也算空节）。
- 未知节名／重复节名 ⇒ 报错。

## 4 四步核对（每条都要真 exit；`> 日志 2>&1; echo $?`，别用管道取状态）

```bash
node tools/build-content.mjs --content-version <新版本> --previous-version <上一版> --order source --minify
cp dist/content.json android/app/src/main/assets/content/content.json
node tools/check-bundled-content.mjs          # 比 dynasties+poems，忽略版本/时间戳
npm test
cd android && JAVA_HOME='<JDK17>' ./gradlew testDebugUnitTest --offline --no-build-cache --rerun-tasks
```

发布前另跑 `node release/check-ready.mjs`（26 项门，含真跑门）；那一步与版本号/签名有关，见 `docs/local-stage-delivery.md`。

## 5 多朝代：**已就绪**，但**没有过真实多组内容**

- **组序**由注册表 `order` 决定：编译器把顶层 `dynasties` 写成「**实际有内容的组**」按 order 升序的**中文值数组**。
- **两端的分组都照这个数组**（Web `groupPoems`；Android 同样要求 `dynasty` 在顶层 `dynasties` 里声明过）。
  Web 里那个按拼音排的 `leftovers` 分支是**给手写 JSON 兜底**的，正常产物走不到。
- **组内次序 ＝ 产物数组次序**（`--order source`；`orderInSource` 升序），客户端**不重排**。
- ⚠ **诚实边界**：至今**没有真实的多组内容**（本库只有「汉」一组）⇒ 多组时的界面表现
  （组头、每组各自「[N] 首」、各组折叠状态互不影响……）**只用夹具验过**。加第二组时应**人工在两端各看一遍**，
  并把「看过」记在这里或 status 里。

## 6 新增朝代要不要改代码？

**不用**——注册表已含 11 个常用 label（先秦…近现代／未详）。只有当你要用表里**没有**的 label
（例如「五代十国」）时，才需要三处一起改：`tools/lib/dynasties.mjs` 加一条（key/label/order）
＋ 同步 `docs/design/content-contract.md` §1.3 ＋ 两端的组名清单。编译器对未声明 label 会**报错并提示这条路径**
（这是刻意的：组名是一次**显式**决定，不做别名猜测）。

## 7 录入时不要做的事

- 不代用户写笔记或任何第一人称内容；不抓整库当素材；不把现代译注当作原文。
- 来源逐字保留（含访问日期与对校本），异文**逐字**写进 `## 详情`，不概括、不改写。
- 不为了「凑齐」而编造底本/异文；查不到就**如实空着或写明未核**。
