# 逐屏评审清单（UI 屏级：内容与排布）

> 2026-10-15 由**对话侧**建立。依据是用户当天的一条判断：**「我们只讨论了一个初步的风格，具体的内容和排布都是没有审核的」** —— 以及我核过记录后确认的、比这更不利的事实（见下「为什么需要它」）。
> 本文件的用途：把「屏上应该有什么 / 不该有什么」逐条摆出来，**一屏一屏过**。它本身**不证明任何东西**，它是**过账的框**——过了就在「结论」列记「已审」，改了就记「待改＋改法」。

## 为什么需要它（证据，不是感觉）

| 事实 | 来源 |
|---|---|
| 用户 2026-10-14 批准的是**风格方向**（静默终端／深墨底），外加一批**决策**（应用名、包名、排序、异文不上界面、单主题、哈希路由、签名方案…） | `docs/interface-decisions.md`、`docs/review-gates.md` A2 |
| 用户选风格时看的 22 张实拍截图，用的是**夹具数据**（5 组、10 首，页头写着「数据：fixture」） | `prototype/screenshots/*-tech.png`（我实看过 hub 那张） |
| 而且那批截图**是「客户端重排」修复之前拍的**——里面次序还是**拼音序**，不是最终采用的底本原次序 | `docs/status.md` 诚实边界一节 |
| 真实内容是 **1 组、19 首**（不是 5 组 10 首） | `dist/content.json` 实测 |
| ⇒ 结论：**「屏级内容与排布」这一层从来没有被过账** | —— |

**本轮撞到的每一个问题都落在这一层**，这就是它存在的理由：

| 已发生的问题 | 属于本清单的哪一格 |
|---|---|
| 两端视觉根本没落地（用了框架默认浅色） | 全部屏（材质与令牌） |
| Web 诗页多出「异文」栏 | 诗页 · 不应有 |
| Web 诗页多出一行诗 `id` | 诗页 · 不应有（用户 2026-10-15 拍板删） |
| 目录页结构与原型不一致（组卡片 vs 组头＋内联） | 目录 · 排布（本质上是**从未过账**，不是实现出错） |
| 「有笔记」标记三份三样（Web「有笔记」／Android 无／原型「笔记」） | 目录与搜索 · 行内容 |
| Android 更新页一处过期文案、一处 Idle 态空行 | 更新页 · 文案与状态 |
| 没有专属图标（A8 时点已过） | 资产 · 启动图标／favicon |
| favicon 在 16px 下必糊（字标的固有性质） | 资产 · favicon（用户 2026-10-15 定为另做无字记号） |

## 怎么用

1. **材料**（由调度侧产出，对话侧不写原型/不截实现图）：每一格一张**真实运行**的图（Android＝模拟器/真机实拍；Web＝本地站点实拍或线上实拍），**不许用原型截图、不许用夹具数据**。
2. **逐格过**：对话侧逐行问「这一格对不对 / 要改什么」，用户拍板；改完的格记「已审（日期）」，未改的记「待改：<改法>」。
3. **结论落到台账**：屏级决定写进 `docs/interface-decisions.md`（决策类）或 `docs/review-gates.md`（门槛类）；**不许只在聊天里说过**。
4. **两端一致性**：同一格的期望默认「**两端守同一句话、不要求像素级一致**」；确有必要不同的，必须**显式记成「有意差异」并写理由**（`docs/design/visual-tokens.md` §4.2 就是干这个的）。

## 诚实边界

- 本清单**没有**列出「颜色具体取什么值」这类已由令牌定死的东西——那些已有逐值断言在守（Web 与原型 57 项同值；Android 读规范逐项比对），不靠人看。
- 本清单**不是**给用户的问卷；它是一张**过账表**。用户只回答「这一格对不对 / 要改成什么」。
- 「未审」不等于「错」——它只表示**还没有人看过并说过话**。
