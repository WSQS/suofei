> ⚠️ 本目录**只是样例**：`content/` 里的真数据一个字没动，产物也没动。采纳与否由用户拍（见 `docs/reviews/h1-content-format.md` 第八节）。
> ⚠️ 本样例演示两件事，**其中第二件仍未定**：① **详情进正文**（用户已定方向）；② **集合级字段上提**（`dynasty/dynastyOrder/era/genre/author/source` 在 19 份里逐字重复）——若不做②，每首诗的 front matter 保持现状，只是详情节进正文。

## 样例一：一首诗的源文件（`poem-13.md`）

见 [`poem-13.md`](poem-13.md)。要点：

- front matter **只剩每首诗自己的东西**（`title`；若不做②则仍保留那些集合级字段）；
- 正文＝**诗行，每印刷行一行**（与现在完全一样）；
- **`## 详情` 之后是详情部分**——它承载「底本与来源 / 异文 / 分段」。

## 一处必须改编译器（否则会出错，不是"可选优化"）

现在的编译规则是「**正文区每行都是一个印刷行**」。加了详情节以后，编译器**必须**在切分点停住——否则「### 异文」这类行会被当成**诗行**编进正文（那会直接污染阅读内容）。

⇒ 所以这条路**不是纯文档改动**，它必然要动 `tools/` 的编译与校验，并同步改契约 §1（现在写着「正文区不写解释、译注、赏析等非原文字句」——详情节是这个规则的**受控例外**）。

## 还没定的两件

2. **集合级字段要不要上提**（上面「②」那一半）。
